# 2026-08-16 生产网络加固：RDS 白名单收窄 + 安全组拆分

> 模块：运维 / 生产网络。**本次没有任何代码改动**，改的全是阿里云端配置。
> 起因是评估「生产数据库密码轮换」，结论是密码不用换，但顺带查出两处网络配置该收。

## 一、起因与结论：密码没换

生产 RDS 的 `db_admin` 密码此前长期以明文存在于本地记忆文件里（已清除），
按"应视为已泄露"评估是否轮换。**查证后结论是暂不轮换**，Frank 拍板：

| 检查项 | 结果 |
|---|---|
| 密码泄露范围 | 只在本机记忆文件（已清除），**未进过 git 仓库** |
| 仓库 / GitHub Actions secrets | 只有 RDS 主机名，**没有密码**（secrets 只有 SSH 三项） |
| 生产持有点 | 只有 `server/.env` 一处；`server/scripts/backup-db.sh` 是**从 .env 读**的，无第二处硬编码 |
| RDS 接入方式 | **只有 VPC 私网接入点** `172.16.0.13`，**没有开公网连接地址** |
| 安全组是否放行 5432 | 否 |
| 是否有被利用迹象 | 未查（需 RDS 连接审计日志） |

即：这个密码**从外网根本用不上**，要用它得先拿到 VPC 内某台 ECS 的 shell；
而拿到 EU-TMS 这台的 root 就能直接读 `.env`，密码泄露与否没有区别。

轮换脚本已备在服务器 `/root/rotate-db-password.sh`（700 权限，不含任何密码，
`read -s` 交互输入 + 自动备份 .env + 按 URL 规则转义写回 DATABASE_URL），将来要换随时可用。
换完必须 `pm2 delete` 再用 ecosystem 起（踩坑 005 + 064）。

## 二、改动一：RDS 白名单从 `/24` 收窄到单机

| | 改前 | 改后 |
|---|---|---|
| `default` 组 | `172.16.0.0/24` | **`172.16.0.11`** |
| `hdm_security_ips` 组 | `100.104.110.0/24,100.104.112.0/24` | 未动（阿里云 DAS 管理地址，隐藏组，动不得） |

**为什么改**：VPC 里还有第二台 ECS `172.16.0.9`（先锋系统），落在原 `/24` 网段内，
网络层能连 EU-TMS 的生产库。Frank 确认两个系统互不访问。

**改前取证**（不是凭猜测就改）：

```sql
SELECT client_addr, usename, datname, count(*), min(backend_start)
FROM pg_stat_activity WHERE client_addr IS NOT NULL GROUP BY 1,2,3;
--  172.16.0.11    | db_admin | germany_box_transport | 6 | 2026-08-03 01:04:18
--  100.104.221.64 | aurora   | rdsadmin              | 2 | （阿里云 DAS）
--  100.104.110.49 | aurora   | postgres              | 1 | （阿里云 DAS）
```

只有 EU-TMS 自己在连，`172.16.0.9` 零连接。

```bash
aliyun rds ModifySecurityIps --DBInstanceId pgm-j6crhh9h8562qvfm \
  --DBInstanceIPArrayName default --SecurityIps 172.16.0.11 --ModifyMode Cover \
  --region cn-hongkong
```

### ⚠️ 这条改动埋了一个雷，必须记住

**白名单现在锁死到 `172.16.0.11` 这个具体 IP。**
将来 EU-TMS 这台 ECS 重建、换机、或私网 IP 发生变化，**数据库会立刻连不上**，
而且症状是"连接超时"，看不出跟白名单有关。

排查「生产突然连不上数据库」时，**先查这条**：

```bash
ssh eu-tms "hostname -I"    # 当前私网 IP 是不是还是 172.16.0.11
aliyun rds DescribeDBInstanceIPArrayList --DBInstanceId pgm-j6crhh9h8562qvfm --region cn-hongkong
```

回滚（放宽回整个网段）：

```bash
aliyun rds ModifySecurityIps --DBInstanceId pgm-j6crhh9h8562qvfm \
  --DBInstanceIPArrayName default --SecurityIps 172.16.0.0/24 --ModifyMode Cover \
  --region cn-hongkong
```

## 三、改动二：安全组拆分

**改前**：两台 ECS 共用系统默认安全组 `sg-j6ch3x980uowk2rpf1zq`，
其中 `25 / 7000 / 10143 / 10993` 对 `0.0.0.0/0` 开放（先锋的邮件服务需要，
EU-TMS 这台上没有任何进程监听）。

**改后**：EU-TMS 独用新建的 `sg-j6cflgbal6ro0kwcohuw`（名称 `eutms-web`）：

| 方向 | 协议 | 端口 | 源/目的 | 说明 |
|---|---|---|---|---|
| 入 | TCP | 22 | 0.0.0.0/0 | SSH。**故意不收窄到固定 IP**——Frank 的宽带 IP 是动态的，锁死后换 IP 就进不去；且已是"禁用密码、仅密钥"（`passwordauthentication no`） |
| 入 | TCP | 80 | 0.0.0.0/0 | nginx HTTP→HTTPS 跳转 + certbot 续期验证 |
| 入 | TCP | 443 | 0.0.0.0/0 | nginx 正式站点 |
| 入 | ICMP | -1/-1 | 0.0.0.0/0 | ping 排障 |
| 出 | ALL | -1/-1 | 0.0.0.0/0 | **显式写一条**，不依赖平台默认策略 |

**执行顺序（关键）**：建组 → 加规则 → 核对规则 → **加入**新组（此时同属两组，规则取并集）
→ 验证 → **移出**旧组 → 重验。先加后移，任何时刻都至少属于一个可用的组，没有失联窗口。

**兜底**：`JoinSecurityGroup` 走 API，**不依赖 SSH**。真锁死了一条命令就能加回旧组：

```bash
aliyun ecs JoinSecurityGroup --RegionId cn-hongkong \
  --InstanceId i-j6c9c2mj1yzlx4gxdbvk --SecurityGroupId sg-j6ch3x980uowk2rpf1zq
```

**先锋那台全程未碰**：仍在原安全组，四条邮件端口规则一条没动。

## 五、关联影响

- **代码**：无任何改动。本次不涉及前后端、数据库结构、迁移。
- **CI/CD**：不受影响。部署仍走 SSH(22) + rsync，新安全组放行 22。
- **证书续期**：不受影响。certbot 用 `--webroot` 走 80 端口，新安全组放行 80。
- **邮件发送**：不受影响。Resend 是**出方向** 587，出方向全放行；已实测可达。
- **OSS**：不受影响，出方向，已实测可达。
- **先锋系统**：不受影响，未碰它的机器和安全组。它与 EU-TMS 互不访问（Frank 确认）。
- **数据库备份**（`/etc/cron.d/germany-box-db-backup`，每天 03:00）：不受影响，
  在 `172.16.0.11` 本机上跑，仍在白名单内；且它从 `.env` 读连接串，将来换密码也会自动跟上。

## 六、确认不受影响的边界

- 后端仍绑 `*:3002` 而非 `127.0.0.1:3002`。公网进不来（安全组未放行 3002），
  同 VPC 也进不来（ufw `deny incoming`）。属可选加固，**本次未改**。
- 生产 `server/.env` 权限仍是 644、属主 `501:staff`（rsync 留下的）。
  只有 root 会登录这台机器，实际风险有限，**本次未改**；真要轮换密码时一并收紧到 600。
- 生产 `/root/.bash_history` 里有 5 行带明文数据库密码的历史命令。
  密码没轮换所以仍然有效，但读它需要 root——而有 root 就能直接读 `.env`。**本次未清**。

## 七、踩坑

见 `docs/踩坑经验库/065_安全组放行不等于端口可达机器上还有一层ufw.md`：
这台机器有 **ufw + 安全组两层防火墙**，判断端口暴露必须两层都看；
`nc` 探测要**看耗时**才能区分"放行但没进程"（约 0.1s RST）和"被丢包"（约 5s 超时）。
