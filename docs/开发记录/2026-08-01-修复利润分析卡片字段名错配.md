# 2026-08-01 修复利润分析卡片字段名错配

## 模块
财务管理（admin 端）

## 问题说明

财务管理页「利润分析」tab 的客户利润卡片：
- 卡片标题（客户名）显示为空
- 所有卡片的 React key 都是 `undefined`，控制台报重复 key 警告

根因：前端 `ClientProfit` interface 的字段名是凭空写的（`client_name` / `revenue` / `cost` / `profit` / `margin`），
而后端 `/api/v1/finance/profit/by-client`（`server/modules/finance/routes.js`）的 SQL 实际返回
`id` / `company_name` / `client_code` / `total_revenue` / `total_cost` / `gross_profit` / `margin_pct` / `order_count`。
属踩坑 003 / 011 的前后端契约不一致，修复前 tsc 已在 640-643 行报 4 个 TS2339 错误。

## 修复方案

按「前端 interface 与 API 保持 snake_case 一致」原则，**只改前端**，后端 SQL 不动：

1. `ClientProfit` interface 重写为与 API 返回完全一致的 8 个字段；
   数值字段类型标为 `string | number`（PostgreSQL NUMERIC/BIGINT 返回字符串，踩坑 002）
2. 卡片 JSX：
   - key 从 `p.client_name` 改为 `p.id`（唯一、稳定）
   - 标题从 `p.client_name` 改为 `p.company_name`
   - 金额从 `fmt(p.total_revenue || p.revenue)` 兜底写法改为 `fmt(Number(p.total_revenue))`（踩坑 002：先 Number() 再格式化）
   - 毛利率 `Number(p.margin_pct ?? 0).toFixed(1)`，兜底用 `??` 不用 `||`（踩坑 011 防护规则 5）

## 修改文件

| `admin/src/pages/FinanceManagement.tsx` | 修改 | ClientProfit interface 重写为 API 实际字段；利润卡片 JSX 改用 company_name/id 并加 Number() 转换 |
| `docs/踩坑经验库/003_前后端字段名不一致.md` | 更新 | 补充本案例：snake_case 也救不了猜出来的字段名 |

## 关联影响分析

- `ClientProfit` 和 `/finance/profit/by-client` 全仓库只有 `FinanceManagement.tsx` 一处引用（已 grep 确认三端），无其他牵连
- 后端 `server/modules/finance/routes.js` 未改动
- tsc 验证：修复前该文件 7 个类型错误，修复后剩 3 个——均为改动前就存在的存量问题
  （`fmt()` 在约 133/734/925 行被传入 `string | number`，属应收/应付账单表，与本次无关，已另立后台任务建议处理）
