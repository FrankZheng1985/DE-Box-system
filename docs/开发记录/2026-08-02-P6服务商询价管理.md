## 功能说明

给一张客户询价单配一套「对多家服务商问成本」的记录，回价填进来后对比、选用，
成本再带到报价单上算毛利 —— 也就是需求 5.3 的「客户询价 ↔ 服务商询价」对照。

### 本阶段范围（Frank 2026-08-02 拍板）

| 问题 | 结论 |
|------|------|
| 询价怎么"发出去" | **只在系统内建记录**，实际内容用询价详情页已有的「复制摘要」粘给服务商，不自动发邮件 |
| 服务商能不能自助回价 | **不做**，carrier-portal 完全不动，由运营收到回复后手工回填 |

### 状态流转

```
PENDING 待回价 ──回价──> QUOTED 已回价 ──选用──> SELECTED 已选用
    │                        │
    ├──不报──> DECLINED      └──不报──> DECLINED
    └──取消──> CANCELLED
```

- 一张客户询价**最多选用一家**：改选另一家时前一家自动降回「已回价」，
  库里还有部分唯一索引 `uq_carrier_inquiries_selected` 兜底
- 已选用的不能取消、不能标记不报价（要先改选别家），避免出现"选用了又没了"的悬空状态
- 已回价/已选用的记录不能删除，只有「待回价」和「已取消」可以删（发错了的补救）

### 成本参考进报价

- 「由此报价」进创建页时自动拉这张询价的服务商成本：**选用了哪家用哪家，没选用就取最低回价**
- 顶部显示成本、时效、预估毛利（**币种不同不算毛利**，乱换算会给出错误的利润数字）
- 提交时把成本写进 `quotations.carrier_cost`，来源记在 `carrier_cost_source_id`
- 换新版本（new-version）沿用上一版的成本：换版本是改客户价，服务商成本没变

## 设计决策

1. **服务商询价不走凭证引擎**（不建 documents、不进单据流），只借编号范围拿唯一号
   `CINQ-YYYYMMDD-0001`。理由：这是内部询价动作，不是对外凭证，
   进凭证表会占 ORD/QUO 一样的凭证号并产生必须冲销的痕迹。

2. **不加 `UNIQUE(inquiry_id, carrier_id)`**。同一家服务商可能因为货量变化被反复询价
   （第二轮、第三轮），唯一约束会把正常业务挡死。防重复改成：发起时若该服务商
   还处在活动状态（PENDING/QUOTED/SELECTED）就跳过，并在返回消息里说明跳过几家。

3. **成本字段在"出口处"统一剥离，而不是在每条 SQL 里挑列**。
   `quotations` 的查询大量是 `SELECT q.*`，新加的 `carrier_cost` 会自动流进
   列表、详情、创建返回值 —— 其中列表和详情客户门户也能调。
   所以在 quotation 模块加了 `stripCarrierCost()`，所有返回报价行的地方统一过一道
   （详见踩坑 026）。

4. **前端单独拆 `CarrierInquiryPanel` 组件**而不是塞进 `InquiryDetail.tsx`：
   详情页已 490 行，把列表 + 两个弹窗塞进去会直接冲到 800 行红线。

## 关联影响清单

1. **`quotations` 表加了两个字段，所有 `SELECT q.*` 的接口都会带出来**。
   已在 quotation 模块的四个出口（列表 / 详情 / 创建 / 新版本）统一剥离；
   `/quotations/:id/versions` 是显式列清单，不含成本，确认安全。
   **以后谁再给 quotations 加敏感字段，记得加进 `COST_FIELDS`。**
2. **客户门户 / 承运商门户不受影响**：两个门户没有任何新增接口调用；
   客户读自己的报价时成本字段已被剥离（冒烟测试有断言）。
3. **财务模块不受影响**：`carrier_cost` 只是报价时的成本快照，
   **不是应付账款** —— 真正的应付仍由 finance 模块在派单后按实际结算产生，两者没有打通，也不应该打通。
4. **订单 / CMR / 清关 / GPS / 放单** 不读 `carrier_inquiries`，确认不受影响。
5. **carriers 表只读**：面板里的服务商选择列表调的是既有 `GET /carriers`，没有改承运商模块。
6. **询价删除会级联删掉服务商询价**（`ON DELETE CASCADE`）；
   删除服务商询价时会先把引用它的报价 `carrier_cost_source_id` 置空，不会被外键卡住。
7. **P5 权限体系回归**：`server/scripts/test-permissions.js` 36 项重跑全过，
   改动没有破坏既有权限行为。

### 测试脚本踩到的两个坑（已修）

1. **清理顺序**：`quotations.carrier_cost_source_id` 指向 `carrier_inquiries`，
   先删服务商询价会被外键挡住。清理必须「先断引用 → 删报价 → 删询价」。
2. **两个测试脚本互相污染**：`test-permissions.js` 会改 op_staff 的权限勾选**且不还原**，
   它跑完再跑 P6 脚本，op_staff 连报价都读不到，断言全歪。
   P6 脚本开头也加了同一段「恢复 op_staff 默认权限」，现在两个脚本谁先跑都不影响对方。
