## 功能说明

将系统中硬编码的基础数据（船司、箱型、币种、国家、港口、车型、特殊要求）迁移到数据库管理，提供统一的 CRUD 管理界面，并替换前端页面中的硬编码常量为 API 动态数据。

## 数据库变更

### 新增表 (7张，md_ 前缀)

| 表名 | 用途 | 特有字段 |
|------|------|---------|
| `md_shipping_lines` | 船司 | country, website |
| `md_container_types` | 箱型 | length_ft |
| `md_currencies` | 币种 | symbol |
| `md_countries` | 国家 | region |
| `md_ports` | 港口 | country_code(FK), port_type |
| `md_vehicle_types` | 车型 | max_weight_kg, max_volume_m3 |
| `md_special_requirements` | 特殊要求 | description |

### 共有字段

所有表统一结构：`id(UUID), code(UNIQUE), name_zh, name_en, is_active, sort_order, created_at, updated_at`

### 索引

每张表创建 `(is_active, sort_order)` 复合索引，港口表额外创建 `country_code` 索引。

## API 端点

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/v1/system/master-data/:type` | 列表（分页+搜索+状态筛选） |
| GET | `/api/v1/system/master-data/:type/options` | 下拉选项（仅活跃项） |
| POST | `/api/v1/system/master-data/:type` | 新增 |
| PUT | `/api/v1/system/master-data/:type/:id` | 修改 |
| PUT | `/api/v1/system/master-data/:type/:id/toggle` | 启用/停用 |

`:type` = shipping-lines | container-types | currencies | countries | ports | vehicle-types | special-requirements

---

## 关键设计决策

1. **不添加外键约束**: 基础数据表仅提供下拉选项来源，不对 orders 等业务表添加外键，避免破坏已有数据
2. **options API 的 value 策略**: 各类型的 value 字段值与业务表已存储的文本值保持一致（如国家用 name_en = "Germany"，船司用 name_en = "MSC"）
3. **软删除**: 停用操作仅将 is_active 设为 false，不物理删除
4. **参数化路由**: 7类数据共用一套 CRUD handler，通过表名白名单映射防止SQL注入
5. **种子数据兼容**: 种子数据值与前端原有硬编码值完全一致
