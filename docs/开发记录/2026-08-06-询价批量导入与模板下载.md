# 询价批量导入 + 导入模板下载（客户门户 + 运营管理端）

**日期**：2026-08-06
**模块**：inquiry（询价）
**需求来源**：Frank —— 询价页要能批量导入，并提供导入模板下载

---

## 一、做了什么

给询价加了 Excel 批量导入，两端都有：

- **客户门户**（`/customer/inquiry`）：「批量导入」按钮，归属客户由 JWT 决定
- **运营管理端**（`/inquiries`）：批量操作条上的「批量导入」按钮，**必须先选客户**

### 表格约定（Frank 2026-08-06 确认）

**一行 = 一件货，按「客户单号」列分组**：

- 同一个客户单号的多行 → 合并成**一张**询价单的多件明细
- 不同客户单号 → 生成**多张**询价单

所以一张表既能录「一票多件」，也能一次导入多票，不用为两种场景做两个功能。

表头字段（服务类型 / 起运地 / 目的地 / 联系人）取该组**第一行**的值，
后续行留空即可；填了不一样的值只给警告不阻断（客户常只在第一行写地址）。

### 三步流程

1. 下载模板（表头按当前界面语言渲染，另附「填写说明」和「示例」两个 sheet）
2. 上传文件 → 后端解析校验，返回**预览**（将生成几张单、每张多少件、错误清单、提醒清单），**一个字都不写库**
3. 确认导入 → 同一套解析逻辑再跑一遍并写库

预览和导入调的是同一个 `analyzeImportFile`，所以「预览看到几张单，导进去就是几张」。
**只要有一条错误就整批不导**——导一半客户没法知道该补哪几张。

### 校验与提醒

| 类型 | 内容 |
|------|------|
| 错误（阻断） | 客户单号必填、服务类型必填/无法识别、起运地和目的地各需国家或城市、件数必须是正整数、尺寸重量必须是数字且非负、该单没有任何货物明细 |
| 提醒（不阻断） | 邮箱格式可疑、同一单号各行表头字段不一致（以第一行为准）、**客户单号在系统里已存在**（重复导入的主要症状） |
| 整份文件不可用 | 文件读不出、没有工作表、缺必需列、没有数据行、超过 500 行 / 200 张单 |

### 解析上的几个细节

- **表头三语通吃**：中/英/德三种模板表头都认，还认「贵司单号」「品名」「数量」等常见别名；
  比对前把大小写、空格、括号、单位符号全去掉，`长(cm)` / `Length (cm)` / `Länge (cm)` 都命中
- **服务类型**认代码（`TRUCK_LTL`）、三语文案、以及 `LTL`/`FTL` 这类简称；模板里该列还带下拉
- **德式数字**：`120,5` → 120.5、`1.250,75` → 1250.75（直接 `Number()` 会得 NaN 或错值）
- **单元格值不是字符串**：ExcelJS 的 `cell.value` 可能是数字/日期/富文本/公式对象，
  直接 `String()` 会得到 `[object Object]`，整列静默变垃圾数据 —— 统一走 `cellToString`
- 体积和 LDM 不用填，按长宽高自动算（口径与 `recalcInquiryTotals` 一致）

## 三、关联影响

### 权限：没有新增权限码，不需要迁移

批量导入 = 批量建单，复用现成的：

- 运营端 `inquiry:create`，门户端 `portal:inquiry_manage`
- 端点上是 `requirePermission('inquiry:create', 'portal:inquiry_manage')` + `requireUserType('OPERATOR','CLIENT')`
- 前端运营端按钮用 `hasPermission('inquiry:create')` 拦，客户门户按钮跟着页面本身的权限走

所以「权限四件套」这次只需要确认没脱节，不需要加迁移脚本（迁移号 122 已被并行对话的代入功能占用）。

### 租户隔离

- 客户门户：`clientId` 一律取 JWT 的 `linkedEntityId`，**前端传的 clientId 直接忽略**（踩坑 016）
  —— 已实测：伪造别人的 clientId 提交，后端仍按 JWT 归属处理
- 运营端：必须显式传 clientId，且做 UUID 格式校验（拿非 UUID 查 uuid 列会抛库错变成 500）

### 被改动波及、已一并处理的地方

- **`POST /api/v1/inquiries` 的建单路径变了**（改调 `createInquiryRecord`），行为与原来逐字段一致：
  同样的凭证参数、同样 20 个字段、同样的明细替换与合计回写、同样的返回值。
  已实测门户单张新建不受影响。
- **三语语言包**与并行对话（代入客户门户）同为改动文件，但改的是不同 key 段，已确认无冲突。

### 确认不受影响

- 询价导出 / 复制摘要 / 询价详情 / 编辑 / 删除：未改动
- 报价、订单、CMR、清关等其它模块：未改动
- 数据库：**无表结构变更、无迁移脚本**

## 五、注意事项

- **上传文件不能走 `api` 客户端**：两个前端的 api 客户端固定带 `Content-Type: application/json`，
  用它发 FormData 会让 multer 认不出 multipart 边界，后端永远收不到文件（前端还以为传成功了）。
  两个弹窗里都用原生 `fetch` + `getAuthHeaders()`，并在注释里写明了原因。
- **单次上限**：500 数据行 / 200 张询价单 / 5 MB；超了直接整份拒绝并提示拆分。
- 模板的数据页**故意不放示例行**，示例单独放在「示例」sheet —— 放在数据页里客户十有八九会连着一起导进来。
- 本次开发在独立 worktree 里进行，期间踩到已归档的踩坑 044（worktree 里 `preview_start` 起的是
  主工作区的旧代码，界面上看不到新按钮），按该记录的做法改用指向 worktree 的启动配置后正常。
