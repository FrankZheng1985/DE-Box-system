# 2026-08-16 本地派送第 2 步：按派送子订单报价

模块：报价（quotation）／运营管理端 + 客户门户 + 后端

对应飞书《EU-TMS 开发意见表》第 7 条，四步计划的**第 2 步**。
第 1 步（询价侧）见 `2026-08-16-本地派送柜与子订单第1步询价侧.md`。
**第 3 步（一柜转 N 单）、第 4 步（履约字段）仍未做。**

---

## 做了什么

苏凌要的是「每一票单独报价 + 整柜合计」，客户按票核价、按柜确认。
改造前 `quotations` 只有一个 `total_price`，装不下逐票价格。

- **新表 `quotation_delivery_lines`**（迁移 130）：一行 = 一票派送的报价
- **合计是算出来的**：`quotations.total_price` = 各行之和，回写在后端做。
  界面上合计不可编辑 —— 让人既能改总额又能改分项，两边迟早对不上
- **报价有版本**，所以逐票行挂在 quotation 下而不是存回询价的子订单上：
  存回去第二版会把第一版覆盖掉，历史版本再也查不回来

### 转单守卫（重要）

第 3 步没做完之前，**三层报价被客户接受会走进旧的转单逻辑**：拿柜级的 `route_to`
建**一张**订单，而三层单的 `route_to` 是空的 —— 建出来是一张没有派送地址、
金额是整柜合计的畸形订单，而且订单是已过账凭证，只能冲销不能删。

所以在 `createOrderFromQuotation` 开头加了一道守卫：询价下有派送子订单就抛错，
两个入口（门户 / 邮件链接）都拦得住。自测里有「接受被拒 + 没有建出订单」的断言。

## 关联影响

**一并改了的：**

- **报价邮件**：本地派送的邮件里加了柜号和逐票报价表。客户是按票核价的，
  只给一个整柜总额他没法核对。
- **`quotations.base_freight`**：三层单下同步为合计值。原来它是「基础运费」，
  三层单没有这个概念，留着旧值会让报价单上出现「基础运费 0 + 合计 500」的矛盾。
- **本地派送的「运输类型」必填**：这是个**既有 bug**，不是本次引入的 ——
  本地派送没有专车/拼车之分（询价侧一直是 null），但报价页把它当必填，
  导致本地派送的报价**一直保存不了**，页面上还看不出是被哪里拦住的。三层单必然撞上，顺手修了。
- **客户门户的失败提示**：原来渲染在页面顶部，会被确认弹窗整个遮住，
  客户只看到「点了没反应」；且 4 秒自动消失。现在错误显示在弹窗内并保留。

**确认不受影响的：**

- 卡派 LTL / 卡车 FTL 的报价：建、改、新版本、详情、邮件全部照旧，
  自测里有专门的回归断言（含「合计没被清零」）。
- `quotation_pricing_items`（定价引擎的费用项）没动，与逐票行是两个维度。
- 订单模块本次一行没动。
