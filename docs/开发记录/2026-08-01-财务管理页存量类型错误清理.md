# 财务管理页存量类型错误清理（fmt 收尾）

- **日期**: 2026-08-01
- **模块**: 运营管理端 · 财务管理（FinanceManagement.tsx）

## 背景

`cd admin && npx tsc --noEmit` 曾存量报 7 个错误，全部集中在 `admin/src/pages/FinanceManagement.tsx`，分两类：

1. **3 处 TS2345**（fmt 调用）：`fmt(amount: number)` 被传入 `string | number`。根因是 `BillRow.amount` 类型为 `string | number`——PostgreSQL NUMERIC 经 API 返回是字符串（踩坑 002）。运行时 `Intl.NumberFormat` 容忍字符串所以页面不炸，但类型检查不干净。
2. **4 处 TS2339**（利润 tab）：`ClientProfit` 接口与后端 `GET /finance/profit/by-client` 真实返回字段不符（踩坑 011 类型问题），且渲染用的 `p.client_name` 后端从不返回（实为 `company_name`），利润卡片客户名恒为空。

**并行撞车说明**：第 2 类问题在本次开发同期已由另一个对话的提交 `0818d81 [财务] 修复利润分析卡片前后端字段名错配` 修复上线（接口对齐 + `company_name` 显示 + 调用处 `Number()` 包裹）。本提交 rebase 时冲突全部采用 main 已上线版本，只保留剩余的 fmt 部分。

## 修改文件

| 文件 | 操作 | 说明 |
|------|------|------|
| `admin/src/pages/FinanceManagement.tsx` | 修改 | `fmt` 签名放宽为 `(amount: string | number)`，内部 `Number()` 转换——一处改完，131 / 732 / 923 三处 `fmt(r.amount)` 类 TS2345 全部消除；以后金额字段直接传 NUMERIC 字符串也合法 |

## 关联影响分析

- **`fmt` 的所有调用点**：传 `number`（含 0818d81 加的 `Number()` 包裹写法）或字符串均合法，运行时行为不变（`Number()` 对合法数字字符串与 `Intl` 直接收字符串等价）。
- **后端不受影响**：纯前端类型修改，未改任何 API。
- **与 0818d81 无冲突**：该提交的接口定义与渲染代码原样保留，本提交仅动 `fmt` 一处 + 注释。

## 验证

- rebase 到含 0818d81 的 origin/main 后，`cd admin && npx tsc --noEmit` → 0 错误。

## 注意事项

- 新增金额字段时沿用此模式：接口标 `string | number`，展示统一走 `fmt()`（内部已做 Number 转换），不要在组件里裸调 `.toFixed()` / `.toLocaleString()`（踩坑 002）。
- **流程教训**：本次与另一对话在同一文件撞车，rebase 冲突以 main 已上线版本为准，避免互相覆盖。多对话并行时开工前 `git fetch` 看一眼同模块有没有新提交。
