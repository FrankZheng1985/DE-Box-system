# 2026-08-16 运营端支持编辑本地派送的三层询价

模块：询价（inquiry）／运营管理端

补齐第 1 步留的尾巴。第 1 步上线时运营端**只能看不能改** ——
详情页的编辑按钮在三层单上是禁用的，因为编辑页只会两层结构，
拿它保存会被后端 400 拒（拒是对的，否则子订单会被洗成空壳）。

---

## 做了什么

运营端询价编辑页现在能改本地派送的柜号和每一票派送：
子单号、收货公司名、地址、收件人、备注，以及每票自己的件明细。
整柜合计实时算，口径和后端两级汇总一致。

详情页的编辑按钮**取消禁用**，那条「还在开发中」的提示文案也一并删了。

## 为什么先抽了两个组件

运营端的件明细表格有 11 列，还带 LDM 手改联动（勾上「手改」才可编辑，
勾的瞬间把当前自动值填进去当起点）。三层结构下每一票都要有这么一张表，
复制一份就是 100+ 行重复，改一处忘一处是迟早的事。

所以先把它抽成 `CargoItemsEditor`，两层和三层共用；行的类型、LDM 换算、
合计、提交前的过滤转换抽成 `cargoItemForm.ts`。
**这是移动现有代码，不是重写** —— 表格的行为、样式、字段一个没变，
两层结构的编辑有回归验证。

## 关联影响

- **两层结构（卡派 LTL / 卡车 FTL）的编辑**：表格换成了组件，但行为一致，
  已实测「打开 → 改货物描述 → 保存 → 查库」正确，且件明细的 `delivery_order_id` 仍为 NULL。
- **提交时两种结构互斥**：有派送票就只发 `deliveryOrders`（带 `containerNo`），
  否则只发 `cargoItems`。后端本来就会拒绝三层单只传 `cargoItems`，前端不该再去撞那道墙。
- 客户门户、后端本次一行没动。

## 一个被门禁拦下来的错

`DeliveryOrdersEditor` 里我一开始写了 `t('excel.toCompanyName')` 和
`t('excel.receiverContactName')` —— 那是**后端**语言包的键（Excel 表头用的），
admin 前端包里根本没有。界面上会直接显示 `excel.toCompanyName` 这串路径。

`npm run check:i18n` 把它抓出来了（「用了但语言包没有」）。改用本端的
`field.receiverCompany` / `field.receiverName`。

**跨端复制 `t()` 调用时要确认键在本端的语言包里** —— 三端语言包是各自独立的。
