## 功能说明

### 1. 需求 5.2：报价邮件 + 三个确认链接

PDF 原问"系统能否读客户回复邮件"。系统没有 IMAP 收信能力，
内容解析成本高且不可靠，按开发计划「四、待确认」第 2 条的建议改为
**邮件里放三个一次性确认链接**。

运营点「发送报价」时，同一笔事务内完成：改状态为已发送 → 签发一次性 token →
把邮件排进 P0 建好的邮件队列（cron 每 2 分钟真正发信）。

客户收到的邮件含订单基本信息、报价金额和三个按钮：**同意 / 待定 / 拒绝**。

| 安全设计 | 做法 |
|---------|------|
| token 强度 | 32 字节随机（256 位），base64url |
| 存储 | 只存 SHA-256 哈希，明文仅存在于那封邮件里 |
| 单次使用 | `used_at` 一旦写上即作废；并发点击靠 `WHERE used_at IS NULL` + 检查 rowCount 拦住 |
| 过期 | 默认取报价 `valid_until`（落到当天 23:59:59）；报价已过期则退回配置的天数 |
| 重发作废旧链接 | 再次发送时把该报价所有未使用 token 标记 `SUPERSEDED` |
| 防扫描器误触 | **GET 只渲染确认页，POST 才改状态** |
| 限流 | 免登录端点挂 20 次 / 60 秒，挡 token 枚举 |
| 追溯 | 记录 `sent_to` / `used_ip` / `used_action` |

> **为什么 GET 不能直接改状态**：Outlook / Gmail 的安全扫描器会预取邮件里的链接。
> 如果 GET 就落库，客户还没打开邮件，报价可能已经"被同意"并自动建单了。

### 2. 需求 8：付款提醒 + 逾期处理

每天 9:00 的定时任务重写：

- **自动把逾期账单标记为 `OVERDUE`**（此前完全没有，逾期账单一直显示"未付款"，财务页逾期统计永远是 0）
- **到期前 N 天提醒** + **逾期催款**，两者都发给客户本人（收件人取开票邮箱优先），不再只发内部站内信
- 天数与开关全部读 `system_settings`，运营在系统设置页可改
- 同一张账单同一天不重复发，避免 cron 重启/补跑轰炸客户

### 3. 需求 8：通知偏好扩展到客户公司维度

`notification_preferences` 从"只按用户"扩展为**用户 / 客户公司二选一**，
`_resolveChannel` 改为三级回退：

```
这个人自己的偏好 → 他所属客户公司的默认偏好 → 系统默认（仅站内信）
```

客户门户设置页新增「通知设置」卡片；`client_admin` 多一个「公司默认」页签。

### 4. 邮件模板机制

P0 的邮件队列对每封邮件都套同一个纯文本模板，渲染不出带按钮的报价邮件。
`notifications` 补 `email_template` + `email_payload`，队列按模板名分发；
认不出的模板名退回通用模板（老数据行为不变）。

## 关联影响分析

- **顺带修掉的越权**：`PUT /system/settings` 此前只挂 `authenticateToken`，
  任何登录账号（含客户门户、承运商门户）都能改信用检查、自动开票等全局开关。已收紧为仅运营。
- **P0 邮件队列不受破坏**：老通知行 `email_template` 为 NULL，队列继续走通用模板，行为完全不变。
- **`notifications.user_id` 放开为可空**：只为支持"纯对外邮件"（收件人不是系统用户）。
  存量行 user_id 都非空；按 user_id 查站内信的语句无需改动（NULL 行天然不匹配）；
  已加 CHECK 卡住"user_id 和 email_to 都为空"的无意义行。
- **order 模块只调用不修改**：`createOrder` / `updateStatus` 的签名与行为未动。
- **carrier-portal 不受影响**：承运商不参与报价流程。
- **确认过不受影响**：CMR / 清关 / 放单 / GPS 不读报价与通知偏好表。

## 遗留 / 后续

1. **⚠️ 邮件目前发出去也会被收件方丢弃 —— 上线前必须先修 DNS**

   2026-08-01 实测发信域名 `box-cargo.de` 的认证状态：

   | 记录 | 现状 |
   |------|------|
   | SPF（TXT `@`） | **不存在** |
   | DKIM（`strato._domainkey`） | **不存在** |
   | DMARC（TXT `_dmarc`） | `v=DMARC1;p=reject;` |

   正是踩坑 012 记的那个最糟组合：DMARC 要求最严格的拒收策略，
   但 SPF / DKIM 一个都没有 → DMARC 判定必定失败 → Gmail / iCloud
   **直接丢弃，连垃圾箱都不放**，而系统日志显示"发送成功"。

   生产 SMTP 本身是好的（`info@box-cargo.de` via smtp.strato.de，账号密码已配）。
   邮箱还在 Strato，DNS 也还指向本机，所以**不用等新域名，现在就能修**：

   ```
   TXT  @        v=spf1 include:_spf.strato.com -all
   TXT  _dmarc   v=DMARC1; p=none; rua=mailto:info@box-cargo.de
   DKIM          在 Strato 邮箱控制面板开启，按提示加它给的 DNS 记录
   ```

   先把 DMARC 降到 `p=none` 观察，确认 SPF/DKIM 都通过后再收紧回 `p=reject`。

   **在 DNS 修好之前，P4 的邮件功能等于停摆**：报价邮件会正常入队、
   `email_status` 会变 SENT，但客户收不到。
   不影响的部分：客户门户「我的报价」照常可以确认、站内通知照常、
   逾期自动标记照常、通知设置照常。

2. **邮件实际投递没在本地验证**：本地无 SMTP，只验证到"入队 + 模板渲染正确"。
3. **报价邮件目前只发一个收件人**（询价联系人 → 客户联系邮箱 → 开票邮箱，取第一个非空）。
   如果业务上需要抄送多人，要扩展成收件人列表。
4. **货物状态更新邮件**未单独接：状态变更已经走 `notificationEngine.notify`，
   客户把 `STATUS_UPDATE` 的邮件开关打开就会收到通用模板邮件。
   如果要更漂亮的专用模板，可复用已存在但一直没被调用的 `statusUpdateEmail`。
5. 单据流 amount 为 NULL 的老问题（踩坑 017）本次仍未动。
