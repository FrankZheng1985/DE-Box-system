# 2026-08-06 · 清除生产日志里的财务数据泄露（测试报告 P3-14）

> 模块：订单
> 来源：`docs/测试报告/2026-08-05-全系统测试报告.md` 第五节 P3-14

---

## 一、问题

`server/modules/order/service.js:499` 有一行 `console.log`：

```js
console.log(`[自动开票] 订单 ${order.order_number} 完成 → 应收 €${clientPrice} / 应付 €${carrierCost}`)
```

**每完成一单就往生产日志写一次订单号 + 应收 + 应付金额**。
全局规范明文「禁止生产环境的 `console.log`」，而这条还带着财务数据。

## 二、改法

**直接删除**，不是用 `NODE_ENV` 挡住。

一开始我改成了 `if (process.env.NODE_ENV !== 'production')` 包一层，
被代码规范钩子拦下——规范里 `console.log` 是**一律禁止**，不接受环境变量豁免。
钩子的判定是对的：

- 这行的信息和它上面刚创建的 AR/AP 凭证**完全重复**，
  真要查这笔账，凭证本身才是权威记录，日志只是影子
- 失败分支的 `console.error('订单完成自动开票失败…')` **保留**——
  那条才是真正需要留痕的

## 三、顺带核查：后端其余 8 处 `console.log` 都是安全的

排查了全后端（排除 `scripts/` 与 `node_modules`），除上面这条外还有 8 处，
**逐条确认都不会在生产反复输出**，故本次不动：

| 位置 | 为什么安全 |
|---|---|
| `middleware/security.js:56` | 在 `requestLogger` 里，而 `app.js:88` 只在 `NODE_ENV !== 'production'` 时才 `app.use` 它——生产根本不挂载 |
| `app.js:173` / `app.js:177` | Socket.IO 连接/断开，**已被 `NODE_ENV !== 'production'` 包住** |
| `app.js:191` | 启动横幅，进程生命周期内只跑一次 |
| `core/db.js:86` | 数据库连接成功，启动时一次 |
| `config/database.js:192 / 211 / 243` | 连接池建立/关闭/测试，启动与关闭时各一次 |

> 记下来是为了避免下次有人"顺手清理"把这 8 处也删掉——
> 启动日志和按请求刷屏的日志不是一回事。

## 四、修改文件

| 文件 | 操作 | 说明 |
|---|---|---|
| `server/modules/order/service.js` | 改 | 删除第 499 行 console.log，留注释说明为何删 |

**无数据库改动，无迁移。**

## 五、关联影响

- **不影响自动开票逻辑本身**：删的只是一行日志，AR/AP 凭证的创建代码一个字没动
- **不影响错误排查**：失败路径的 `console.error` 原样保留
- **确认不受影响**：`scripts/` 下的脚本大量使用 `console.log`，那是 CLI 工具的
  正常输出（体检脚本、迁移脚本都要给人看结果），不在本次范围内

## 六、暴露出的缺口：后端完全没有 lint

这条能长期存在，根因是 **`server/` 没有任何 ESLint 配置，也没有 lint 脚本和依赖**。

2026-08-04 那轮给三个前端补了 `.eslintrc.cjs`（其中就有 `no-console` 规则），
但 4 个包里漏了后端这个——而后端恰恰是 `console.log` 后果最重的地方
（前端打日志只脏浏览器控制台，后端打日志是往生产服务器写业务数据）。

补后端 lint 需要新增 devDependency，按规范要先跟 Frank 确认，**本次未做**。
