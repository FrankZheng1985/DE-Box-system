# 2026-08-07 服务商询价邮件直发（含多询价邮箱登记）

## 背景

服务商询价（P6 · 需求 5.3）此前只做登记管理：发起询价只在系统里建记录，
实际询价内容靠运营手动「复制摘要」粘给服务商（2026-08-02 Frank 定的方案）。
本次 Frank 调整决定：**系统直接给服务商发送询价邮件**，并支持同一服务商
登记多个接受询价的邮箱、同时发送。

## 功能说明

1. **服务商登记询价邮箱**：新建/编辑承运商时可填多个询价邮箱（逗号分隔），
   详情页可见。发询价邮件时全部作为收件人；一个都没登记则回退用联系邮箱。
2. **发起询价即发邮件**：发起弹窗新增「同时发送询价邮件（英德双语）」开关，
   默认勾选。每家服务商收到一封英德双语询价邮件（路线、货物、柜型、特殊要求、
   补充要求），直接回邮件报价即可。弹窗里逐家显示将发往的邮箱，
   没有邮箱的服务商给出黄色提示。
3. **邮件走既有队列**：复用 notifications 表 + email-queue 的异步发送机制
   （重试 3 次、PM2 cluster 防重发、失败留痕），SMTP 慢/挂了不拖住发起接口。
4. **状态可见 + 可补发**：询价列表单号下方显示邮件状态徽标
   （待发送/发送中/已发送/发送失败，悬停看收件人和失败原因）；
   待回价的记录可点「发邮件/重发邮件」补发（发起时没勾、后补邮箱、发送失败三种场合）。
5. **无邮箱如实报告**：发起时有服务商没登记任何邮箱的，记录照建，
   但用醒目提示点名哪几家没发出去（不装作全部成功）。

## 关联影响分析

- **批量发起接口向后兼容**：老调用不传 sendEmails 按 true 处理；data 返回结构不变，
  只是多了 summary。原 34 项 P6 冒烟测试（test-carrier-inquiry.js）全部通过。
- **notifications.email_to 放宽为 TEXT**：只影响列宽，varchar→text 是元数据变更；
  email-queue 的 langForRecipient 对逗号串查不到用户 → 回退中文，
  而 CARRIER_INQUIRY 模板不吃 lang 参数，无影响。
- **敏感信息**（踩坑 026 自查）：inquiry_emails 顺着 carriers 的 SELECT * 只会
  流向运营端（carrier 模块整体 requireUserType('OPERATOR')），门户拿不到；
  询价邮件 payload 不含客户名/客户价格（有冒烟断言）。
- **确认不受影响**：客户门户、承运商门户零改动；报价邮件/账单提醒等
  既有邮件模板不受 TEMPLATES 新增条目影响。

## 注意事项

- **生产部署顺序**：先备份 RDS → 跑迁移 125 → 部署后端（pm2 delete all 重启）→
  部署前端。邮件由 cron 每 2 分钟轮询发送，发起后最多延迟 ~2 分钟寄出。
- 服务商回价仍是运营手工回填（`/reply`），本次没有做服务商自助回价链接。
- 邮件里引导服务商**直接回复邮件**，回信落到 info@kalunasped.com
  （Cloudflare Email Routing 转发），注意查收。
