# 2026-08-04 · 修门户「公司设置」保存后数据丢失

> 模块：客户门户 / 承运商门户 / 后端 system
> 迁移：119
> 来源：P9 第 1 次对话就记在「没改的既有问题」里，本次清掉

---

## 问题

承运商门户「公司设置」有 8 个输入框、客户门户「账户设置」有 3 个公司字段，
它们 PUT 的都是 `/system/settings/account`。而那个接口只认四个字段：

```js
const { email, phone, displayName, language } = req.body
```

**其余字段发过去直接被静默丢掉**——公司名、税号、地址、银行账户、联系人，
填完点保存，页面弹「保存成功」，刷新回来一个字都没有。

这类 bug 比报错更坏：用户以为存上了，运营那边也以为承运商没填。

---

## 改法

新增一对接口，按登录方类型写对应的主数据表：

| 登录方 | 写哪张表 | 可写字段 |
|---|---|---|
| CLIENT | `clients` | 公司名 / 税号 / 联系人 / 邮箱 / 电话 / 地址 / 城市 |
| CARRIER | `carriers` | 上述 + **银行名 / 账号**（迁移 119 新加两列） |

- `GET /system/settings/company`
- `PUT /system/settings/company`

两个门户改成：个人信息（邮箱/电话/显示名）继续走 `/settings/account`，
公司资料走新接口。承运商门户 8 个字段全部真正入库。

### 迁移 119 为什么只给 carriers 加银行字段

我们是**付钱给承运商**的一方，收款账户本来就该记在承运商档案里——
现在这信息散在邮件和微信里，运营每次付款都要翻聊天记录。

客户是我们开票收钱的对象，**不需要存客户的收款账户**，所以 `clients` 不加。

## 🔒 租户隔离（踩坑 016 / 023 / 035）

这是个门户可写接口，安全上做了四件事，并在生产上逐条验过：

| 措施 | 生产验证结果 |
|---|---|
| 改哪家公司**只认 JWT 里的 `linkedEntityId`**，不接受前端传公司 id | 每个绑定账号只解析到自己那家 ✅ |
| 运营账号没有 `linkedEntityId` → 403 | `admin` / `Kiu` 均被拒 ✅ |
| 字段白名单，不拼接任意列名 | 请求体混进 `status` / `performance_score` / `id`，实际只写 `company_name` / `bank_name` ✅ |
| 绑定指向已删除的公司记录时明确 404，不静默返回空 | `speedtrans` / `siemens` 返回「关联公司不存在」✅ |

> 第四条对应踩坑 035：绑定悬空时如果静默返回空，用户会以为"我公司资料是空的"，
> 填完保存还会 `UPDATE ... WHERE id = <不存在>` 影响 0 行却提示成功。现在直接报错。

## 🔗 关联影响

1. **`/settings/account` 一行没动**，只是不再被拿来存公司资料。
   admin 的系统设置页仍然用它存邮箱/电话/语言，不受影响。
2. **迁移 119 是纯加列**，2 家承运商现有数据未受影响（两列均为 NULL）。
3. **确认不受影响**：订单、财务、CMR 等业务模块均未触及；
   admin 的客户/承运商管理页走的是各自的 `/clients/:id`、`/carriers/:id`，
   和这个门户接口互不干扰。
