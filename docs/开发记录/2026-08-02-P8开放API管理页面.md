## 功能说明

P8 第一阶段上线了开放 API 平台，但密钥管理只能 SSH 上服务器跑脚本。
本阶段把它搬进运营管理端：**系统设置 → 开放 API 对接**（`/settings/open-api`）。

- **密钥管理 tab**：签发（弹窗显示明文一次，带复制按钮）、编辑（名称/限速/IP 白名单/备注）、
  停用/启用（即时生效）、换钥匙（旧钥匙即刻失效，二次确认有明确后果提示）
- **请求日志 tab**：全部推送请求留痕查询，按合作方/结果/对方单号筛选，分页
- 权限码 `open_api:manage`（迁移 113），默认分配 sys_admin + op_manager；
  op_staff 刻意不给——密钥能以客户名义建单，等同"替客户下单"的钥匙

## 关联影响分析

1. **对外 API（/api/open/v1）行为零改动**：service.js 只加了 generateKey 导出。
2. **create-api-key.js 脚本保留且可用**（冒烟里实测）：服务器上没有浏览器时仍可应急用。
3. **签发人即操作人**：admin 签发的钥匙 created_by 是当前登录运营，比脚本兜底的 sys_admin 语义更准（踩坑 019 的 resolveActingUser 顺序不变）。
4. **check-permission-menu-sync.js 改动向后兼容**：109 仍在扫描范围内，权限字典只增不减（顺带把 002_seed_data.sql 里的历史权限 INSERT 也纳入字典，只影响"未使用"参考列表，无害）。
5. **刻意不支持**：改 partner_code（幂等键的一半，历史单据会对不上）、换挂靠客户（等于把对方之后的单挂到另一家名下）——要换就停用旧钥匙重新签发。
6. **确认不受影响**：Sidebar 菜单不变（入口在系统设置卡片里，与 master-data 等同级）；客户/承运商门户零改动。
