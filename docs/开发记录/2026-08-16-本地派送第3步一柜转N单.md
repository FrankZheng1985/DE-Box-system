## 做了什么

客户接受一张本地派送报价后，按票生成 **N 张订单**，一票一张：

| 订单字段 | 取值 |
|---|---|
| `pickup_address` | 柜的取件地址（N 张相同） |
| `delivery_address` | **该票**的派送地址（含公司名、收件人） |
| `client_price` | **该票**的报价 |
| `cargo_quantity/weight/volume` | **该票**的汇总 |
| `container_no` | 柜号（N 张相同，用它把一个柜串起来） |
| `source_quotation_id` | 报价 ID（迁移 131 新增） |
| `status` | `PENDING_DISPATCH` |

**第 2 步加的转单守卫已删除**，连同 `message-codes.js` 和三端语言包里那条
`LOCAL_DELIVERY_CONVERT_NOT_READY`。

### 为什么加 `orders.source_quotation_id`

`quotations.converted_order_id` 上有部分唯一索引（迁移 107），**一张报价只记得住一张订单**。
那个索引不能删——它防的是「一张订单被两张报价重复转出」。所以反过来在订单侧记来源：
N 张订单都指回同一张报价，`converted_order_id` 继续记第一张，
前端「跳转到订单」的既有逻辑不用改。

### 事务边界

**全程一个事务**：任何一票失败（信用超额、取号失败…）整批回滚，报价退回原状态。
绝不允许「转了一半」——订单是已过账凭证，只能冲销不能删，半批订单没法自动收拾。
自测里有专门的回滚断言。

逐单的「新订单」站内通知全部跳过（`skipNewOrderNotify`）——一个柜三十票就是三十条通知。

## 顺手修的既有 bug：信用超额时报 TypeError

自测跑超额场景时，客户看到的错误是：

```
clientData.credit_limit.toFixed is not a function
```

`credit_limit` 是 NUMERIC，pg 驱动回来是**字符串**（踩坑 002 的老问题）。
`credit-manager.js` 里 `<= 0` 和大小比较靠 JS 隐式转换侥幸能用，
但 `.toFixed()` 只在**超额分支**里调用 —— 平时跑不到，一旦客户真的超额就炸，
而且炸出来的是技术栈信息而不是超额说明。

修完之后是：「信用敞口 €1003499.00 严重超出额度 €200000.00 (401.7%)，订单被阻止」。

这个 bug 影响**所有**业务类型的超额场景，不只本地派送。

## 自测（本地库，27 条断言全过）

一柜 3 票 → 接受 → 3 张订单：数量、金额按票拆（180.5/219.5/100，合计 500）、
货量按票拆、柜号一致、取件地址一致、派送地址各不相同、收件人跟着那一票走、
每张都指回同一张报价、状态都推进到待派送、3 条报价→订单单据流。

另有：报价转 CONVERTED、`converted_order_id` 记第一张、**重复接受被拒且不多建单**、
**信用超额整批回滚（一张没建、报价退回 SENT）**、两层单回归（仍是 1 张、落 PENDING_REVIEW）。

门禁：`check:i18n` 三语一致、`tsc` 无错、`eslint` 0 error、`build` 通过。测试数据已清理。

### 自测里发现的一件事（未修）

单据流 `QUO_TO_ORD` 的 **`amount` 全是 NULL**。原因是凭证引擎 `createDocument`
已经用 `sourceDocType/sourceDocId` 建了流，`order/service.js` 里那句显式的
`createFlowLink`（带 amount）撞上 `ON CONFLICT DO NOTHING` 从没生效 ——
**这正是踩坑 017 记过的问题，至今仍在**，影响所有 QUO→ORD，不只本次。
本次未动，建议单独立项。
