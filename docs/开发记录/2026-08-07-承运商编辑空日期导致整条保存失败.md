# 2026-08-07 · 承运商编辑：空日期导致整条保存失败

**模块**：承运商（carrier）

## 问题

管理端「运输公司 → 编辑 → 保存修改」，若许可证有效期 / 保险有效期为空，后端报
`invalid input syntax for type date: ""`，**整条 UPDATE 回滚**——同一次提交里勾的
车辆类型、改的服务国家也一起没存进去。

## 根因

两层叠加，详见 `docs/踩坑经验库/059_空日期以空串进SQL会让整条保存失败连带其他字段一起丢.md`：

1. `<input type="date">` 留空提交的是 `''`，后端 PUT 的 `!== undefined` 判断放行了它，
   `''` 进 Postgres 的 `date` 列直接报错，事务回滚带走同批所有字段。
2. **日期回填本身也是坏的**（踩坑 039 同款）：`date` 列经 pg 驱动 + JSON 序列化变成
   UTC ISO 串（库里 2028-12-31 → `"2028-12-30T16:00:00.000Z"`），这串塞给 date 框是
   非法值，浏览器静默显示空白。所以用户什么都不改点保存也会触发。

> 只修第 1 条会让 bug 从"显式报错"变成"每次保存悄悄把日期清成 null"，必须两条一起修。

## 修改文件

| 文件 | 操作 | 说明 |
|---|---|---|
| `server/modules/carrier/routes.js` | 新增 + 调用 | 加 `DATE_FIELDS` 与 `normalizeDateFields()`，在 POST `/` 和 PUT `/:id` 入口把空串日期转 `null` |
| `admin/src/pages/CarrierEdit.tsx` | 修改 | 引入 `toDateInputValue`，`licenseExpiry` / `insuranceExpiry` 回填改走它 |
| `docs/踩坑经验库/059_*.md` | 新增 | 踩坑记录 |

## 关联影响

- **新建承运商（`CarrierList.tsx` 的弹窗表单）**：它提交时已经写了 `form.licenseExpiry || undefined`，
  本来不会触发。后端这次统一兜住后，前端就算哪天漏了这个 `|| undefined` 也不会再炸。
- **承运商详情页 `CarrierDetail.tsx`**：只读展示，走 `formatDate()`，不受影响（已确认）。
- **导出 Excel（`carrier/routes.js` 的 `/export`）**：读的是库里的值，日期为 null 时输出 `-`，不受影响。
- **其他带日期的页面**（OrderEdit / OrderCreate / QuotationCreate / ShippingRelease /
  FinanceManagement / CarrierInquiryPanel）：**本次未改**。它们各自的后端接口是否也用
  `!== undefined` 放行空串，没有逐个排查，属于同类风险但不在本次范围内。
- 数据库表结构、权限码、路由均未改动。

## 实测验证（本地 localhost:3002 + :5174，跑的是 worktree 的代码）

1. 直接打接口：PUT 带 `licenseExpiry: ''` + `vehicleTypes` + `serviceCountries`
   → HTTP 200，查库 `license_expiry = null`，车型和服务国家**都真的落库**。
2. 走真实界面：打开编辑页 → 两个日期框正确显示 `2028-12-31` / `2027-06-30`
   （修复前是空白）→ 清掉许可证有效期、勾两个车型 → 保存
   → 跳详情页，「许可证有效期」显示 `-`，「保险有效期」仍是 `2027/06/30`（没被误清）
   → 查库确认 `license_expiry = null`、`vehicle_types` 多了刚勾的两项。
3. `npx tsc --noEmit` 通过；`eslint CarrierEdit.tsx` 无新增错误（1 条既有 warning）。

测试改动的本地数据已还原。

## 备注：本地库有一处与生产不一致（不用改代码）

本地 `carriers.vehicle_types` 还是旧的中文标签写法 `["Curtain Side","Flatbed"]`，
而车型选项已统一成代号（`CURTAIN_SIDE`），所以本地编辑页的车型勾选框回填不上。
迁移 `126_carrier_vehicle_types_to_code.sql` 就是干这个的，本地库没跑过而已，
生产已执行。**属于本地数据陈旧，不是代码问题。**
