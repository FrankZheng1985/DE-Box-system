# 2026-08-06 前端基础组件抽取（Toast / 分页 / 表单控件）

**模块**：运营管理端（admin）前端
**需求来源**：Frank 要求做一次前端系统分析，并按报告的「第一梯队」动手治理
**性质**：纯重构，无业务逻辑改动、无接口改动、无数据库改动

---

## 一、为什么做

分析发现三类重复（详见 `docs/前端架构分析报告.md`）：

1. **Toast 写了 8 遍**，而且签名还不一致 —— 3 个页面是「顶部居中、无图标、只能报成功」，
   5 个页面是「右上角、带图标、能区分成败」。同一个东西长了两副面孔。
2. **分页 UI 写了 11 遍**，行为参差：有的只有「< 1/5 >」，有的带 5 个固定页码，
   只有 OrderManagement 带省略号。
3. **表单四件套写了 2 遍**（OrderCreate / OrderEdit），样式一模一样，
   只有 `SelectInput` 的 `disabled` 支持不一致。

---

## 二、做了什么

### 1. 新增 `components/Toast.tsx`

统一成右上角带图标那一种 —— 因为它能表达失败态，而顶部居中那版做不到。
`type` 默认 `'success'`，所以原来不传 type 的三个页面调用处一行都不用改。

### 2. 新增 `components/Pagination.tsx`

取 OrderManagement 那份最完整的省略号算法作为统一实现
（`1 ... 8 9 10 ... 20` 这种，首尾页始终可见，中间至少 3 个）。
`total <= 0` 时组件自己返回 `null`，所以各页面外层的 `{total > 0 && ...}` 判断可以一并去掉。

### 3. 新增 `components/form/index.tsx`

Label / TextInput / SelectInput / TextArea / SectionTitle 五个，参数取两边超集
（`SelectInput` 保留 OrderEdit 那版的 `disabled`）。

## 四、关联影响

**已一并处理**
- 删掉内联 Toast / 分页后残留的未使用 import（`CheckCircle`、`AlertCircle`、
  `ChevronLeft`、`ChevronRight`）已全部清理 —— 这些会让 `npm run lint` 直接报 error（见踩坑 050）
- 各页面不再使用的 `const totalPages = ...` 变量已一并删除
- `OrderManagement.tsx` 里本地已有 `interface Pagination`（分页元数据类型），
  组件改用 `import PaginationBar from '../components/Pagination'` 别名导入避开重名

**有意为之的视觉变化**
- CMRManagement / CustomsManagement / ShippingRelease 三个页面的 Toast
  从「顶部居中、纯绿、无图标」变成「右上角、带图标」，与其余五个页面一致
- ClientList / CarrierList / CustomsManagement / ShippingRelease / CMRManagement /
  QuotationManagement / FinanceManagement / MasterData 的分页从「< 1/5 >」升级为带页码按钮
- Notifications 的分页容器内边距从 `px-6 py-4` 统一为 `px-4 py-3`

**确认不受影响**
- **客户门户、承运商门户完全未改动** —— 本次只动 admin
- 后端、数据库、权限、i18n 语言包均未改动（分页用的 4 个 key
  `common.totalCount / page / prevPage / nextPage` 三语原本就齐全）
- 各页面的数据加载、筛选、搜索逻辑一行未动，分页 state 变量名也保持原样
