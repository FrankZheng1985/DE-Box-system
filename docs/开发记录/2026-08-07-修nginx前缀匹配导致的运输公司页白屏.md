# 2026-08-07 · 修 nginx 前缀匹配导致的「运输公司」页白屏

> 模块：服务器 nginx 配置（**无代码改动，无迁移**）
> 发现：想在生产验车型下拉，直接输网址进 `/carriers`，一片空白

---

## 一、问题

管理端「运输公司」页，**从侧边栏点进去正常，直接输网址或按 F5 就整页空白**。

根因：`location /carrier` 是**前缀匹配**，`/carriers` 同样以 `/carrier` 开头，
被承运商门户接走了。浏览器拿到承运商门户的 `index.html`，
而它的前端路由里没有 `/carriers`，于是渲染空白。

页内点击是 React Router 前端跳转、不经过 nginx，所以**永远测不出来**。

详见踩坑 **057**。

## 二、改法

三个门户 location 都加结尾斜杠，各配一条精确匹配处理裸路径：

```nginx
location = /carrier { return 301 /carrier/; }
location /carrier/ {
    alias /var/www/germany-box-system/carrier-portal/dist/;
    include snippets/eutms-security-headers.conf;
    try_files $uri $uri/ /carrier/index.html;
}
```

`/admin` 和 `/customer` **一起改**：今天只有 `/carriers` 撞上，
但 `/admin` 会吃 `/administrators`、`/customer` 会吃 `/customers`，同一个隐患。

## 三、执行与验证

1. **改前取基线**：写了个探测脚本，跑 14 条路径记下「状态码 + 返回哪个 SPA」
2. **备份**：`/etc/nginx/snippets/eutms-app.conf.bak-20260807-195948`
3. **`nginx -t` 语法检查**通过后才 `systemctl reload`（平滑重载，不断连接）
4. **改后跑同一套探测，逐行 diff**

### diff 结果：14 条里**只有 1 行变化**

```
< /carriers   200  KALUNA SPED 承运商门户     ← 改前（错）
> /carriers   200  KALUNA SPED 运输管理系统   ← 改后（对）
```

其余 13 条（首页 / 登录 / 订单 / 客户 / 清关 / 设置 / 三个门户首页 /
门户登录页 / API 健康 / 404 兜底）**一字未变**。

## 四、顺带把 nginx 配置纳入了版本管理

原本这次改动只存在于服务器上、git 里零记录——**重装服务器修复就丢了**。
所以把线上生效的这份存进仓库：`deploy/nginx-eutms-app.conf`。

- **它不会被 CI 自动部署**，改了必须手工 `scp` 到
  `/etc/nginx/snippets/eutms-app.conf`，再 `nginx -t` + `reload`（文件头写了流程）
- 回滚靠服务器上的备份：
  `cp /etc/nginx/snippets/eutms-app.conf.bak-20260807-195948 /etc/nginx/snippets/eutms-app.conf && nginx -t && systemctl reload nginx`

### ⚠️ 顺带发现：`deploy/nginx.conf` 早就过时了

仓库里原有的 `deploy/nginx.conf` **只有 `/admin` 和 `/customer`，
连 `/carrier` 都没有**，也不是线上的 snippets 结构——显然很久没同步过。
照着它改会得到一份错的配置。已在新文件头部写明「以本文件为准」。
要不要删掉或重写那份旧的，是独立的事，本次未动。

## 五、关联影响

- **无代码改动、无数据库改动、无迁移**，不需要 CI 部署。
- 三个门户的访问路径**对外完全不变**（`/carrier/` 等仍照常工作，
  裸路径多了一次 301 跳转）。
- 管理端所有一级路由已核对：`/carriers` `/clients` `/cmr` `/customs`
  `/dashboard` `/finance` `/gps` `/inquiries` `/invoice-templates` `/login`
  `/notifications` `/orders` `/quotes` `/settings` `/shipping-release` `/system`
  ——现在没有任何一条会被三个门户前缀吃掉。
