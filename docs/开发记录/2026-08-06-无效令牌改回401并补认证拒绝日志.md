# 2026-08-06 · 无效令牌改回 401 并补认证拒绝日志

## 背景

生产切换 JWT_SECRET（去掉硬编码兜底）后，所有旧会话的令牌签名校验失败，
`authenticateToken` 把这种情况报成 403，前端统一显示「没有权限访问此资源」
且不清登录态，用户卡在坏令牌上全站不可用。详见踩坑 043。

## 修改内容

| 文件 | 操作 | 说明 |
|------|------|------|
| `server/middleware/auth.js` | 修改 | 无效令牌（非过期）分支：403 → 401；新增 `[认证拒绝]` console.warn 日志（记 error.message 和请求路径） |
| `docs/踩坑经验库/043_无效令牌回403让换密钥后全站看似权限故障.md` | 新增 | 踩坑记录 |

## 关联影响分析

1. **三端前端（admin / customer-portal / carrier-portal）无需改动**：
   三份 `api.ts` 对 401 的处理已存在（清 `localStorage` 登录态 + 抛
   `sessionExpired`），本次改动正是让无效令牌走进这条已有的自愈路径。
2. **messageCode（P9 三语）不受影响**：`msg: '无效的认证令牌'` 文案未变，
   `server/middleware/messageCode.js` 按文案映射出 `INVALID_TOKEN`，与状态码无关；
   三端语言包里 `apiMessage.INVALID_TOKEN` 条目保留，继续生效。
3. **`optionalAuth` 不受影响**：它对无效令牌本来就静默放行，没有状态码。
4. **开放 API（open-api 模块）不受影响**：走独立的 API key 认证，不经过
   `authenticateToken`。
5. **无测试断言依赖旧 403 行为**：已全库搜索确认。

## 行为变化（用户可见）

- 之前：令牌失效的用户停留在页面上，处处报「没有权限访问此资源」；
- 之后：第一个请求收到 401，前端清登录态并提示会话过期，回登录页重新登录即恢复。

## 部署

push 到 main 由 GitHub Actions 自动部署（构建三端 + rsync + pm2 重启）。
部署后验证：`curl -H 'Authorization: Bearer bad.token' https://kalunasped.com/api/v1/notifications/unread-count`
应返回 **HTTP 401**（改前是 403）。
