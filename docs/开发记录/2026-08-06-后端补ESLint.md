# 2026-08-06 · 给后端补 ESLint

> 模块：server 构建配置
> 背景：2026-08-04 给三个前端补了 ESLint，**4 个包里漏了后端**。
> 同日查出 `order/service.js` 往生产日志写应收应付金额（测试报告 P3-14），
> 能长期没人发现正是因为后端没有 lint。Frank 同意补，本次落地。

---

## 一、为什么后端比前端更需要这条

前端打日志只脏浏览器控制台；**后端打日志是往生产服务器写业务数据**。
P3-14 那条每完成一单就写一次「订单号 + 应收 €x / 应付 €y」，
没有 lint 就没有任何机制拦得住下一条。

## 二、配置

新增 `server/.eslintrc.cjs`（Node + ESM，`eslint:recommended`）：

| 规则 | 取值 | 说明 |
|---|---|---|
| `no-console` | error，放行 `error` / `warn` | 全局规范「日志规范」 |
| `no-unused-vars` | error，`^_` 前缀豁免 | 全局规范 |
| `scripts/**` 覆盖 | `no-console: off` | CLI 工具要把结果打给人看，是正当输出 |

`server/package.json` 加 `lint` 脚本，并**显式声明 `eslint` 依赖**——
不靠根目录的依赖提升（踩坑 034 就是栽在"借用被提升的依赖"上）。

### ⚠️ 一个覆盖不到的文件，必须说清楚

`server/utils/i18n.js` 用了 ES2025 的 import attributes：

```js
import zhPack from '../i18n/locales/zh.json' with { type: 'json' }
```

eslint 8 的 espree 9 解析不了（`ecmaVersion` 最高 2024，填 2025 报
`Invalid ecmaVersion`）。要覆盖它得升 eslint 9 + 换 flat config，会连带动三个前端，
属于独立任务。**本次把它加进 ignorePatterns，也就是说这个文件目前不受 lint 保护**
——已在配置里写明代价，不假装它被覆盖了（踩坑 038 的教训）。
全后端仅此一处用该语法（已全仓库确认）。

## 三、清掉的 24 个错误

### 8 处 `console.log`：全部加显式豁免，一个都没删

这 8 处**逐条确认过不会在生产反复输出**，用 `// eslint-disable-next-line no-console`
加理由注释保留，而不是放宽规则——这样每处例外都可审计，
新写的 `console.log` 照样会被拦：

| 位置 | 豁免理由 |
|---|---|
| `app.js:174 / 179` | 已被 `NODE_ENV !== 'production'` 包住 |
| `app.js:194` | 启动横幅，进程内只输出一次 |
| `config/database.js` ×3 | 连接池建立 / 关闭 / 自检，启动与退出时各一次 |
| `core/db.js` | 连接自检，启动时一次 |
| `middleware/security.js` | `requestLogger` 整个中间件只在非生产才被 `app.js` 挂载 |

> 踩过的小坑：`eslint-disable-next-line` 后面若跟**两行**注释，
> 「next line」指向的是第二行注释而不是代码，豁免会失效。理由要写在指令**上方**。

### 16 处未使用变量

大多是残留的 import 与死变量，直接删。三处需要说明：

| 位置 | 处理 | 为什么 |
|---|---|---|
| `middleware/errorHandler.js` | `next` → `_next`，**不能删** | Express 靠入参个数（arity === 4）识别错误处理中间件，删了它就退化成普通中间件，错误再也进不来 |
| `modules/carrier/routes.js:90` | 加 `_` 前缀 + 注释，**未改行为** | 见下方"顺带发现" |
| `scripts/` 三处 | 加 `_` 前缀而非删除 | 冒烟脚本里"建好备用"的对象，删掉可能连带删掉必要的副作用调用 |

## 四、顺带发现（未修，等 Frank 定）

**`GET /carriers/match` 接收 `routeFrom` / `routeTo` / `vehicleType` 三个筛选参数，
但从头到尾没用过**——接口返回全部承运商，筛选条件被静默忽略。

这和 2026-08-04 在 `OrderCreate.tsx` 发现的是同一类问题（参数收了不用）。
可能是有意为之（让运营看着准时率/覆盖路线自己挑），也可能是没做完。
**属业务决策，未擅自改动行为**，只加了 `_` 前缀和注释保留契约可见性。

另注：`modules/shipping-release/routes.js` 删掉的是整行 ERP 引擎导入
（`documentEngine` / `notificationEngine` / `NOTIFICATION_TYPES` 全未使用）。
核查过它直接写的是 `shipping_releases` 和 `orders`，都是业务表不是凭证表
（`documents`），**不违反「凭证表只能走引擎」那条架构规则**，那个 import
应是复制粘贴留下的。
