# 2026-08-07 客户门户草稿报价改由后端过滤（安全修复）

**模块**：报价（quotation）、询价（inquiry）、客户门户

## 问题

客户门户「我的报价」页靠前端 `.filter(q => q.status !== 'DRAFT')` 把草稿藏起来，
后端接口没有任何状态过滤。客户带自己的 token 直接调接口，就能看到运营还在编、
尚未发送的报价及其 `total_price`。

是真实漏洞，不是理论风险：本次把过滤常量临时置空做了对照实验，
改前 4 个接口都会把草稿连金额一起返回（详见踩坑 054）。

> 服务商成本 `carrier_cost` 不在泄露范围内 —— 它早在 P6 就按
> `carrier_inquiry:view` 权限单独剥离了，客户任何情况下都拿不到。

## 修改文件

| 文件 | 操作 | 说明 |
|------|------|------|
| `server/modules/quotation/service.js` | 新增导出 | `CLIENT_HIDDEN_STATUSES = ['DRAFT']`，客户不可见状态的唯一定义处 |
| `server/modules/quotation/routes.js` | 修改 | 新增 `isClientUser()`；列表加 `AND q.status <> ALL(...)`；`loadQuotationWithAccessCheck` 对客户的草稿回 404；版本列表加同款过滤 |
| `server/modules/inquiry/routes.js` | 修改 | 新增 `isClientUser()` / `hideDraftQuotationSql()`；询价详情的报价子列表、询价列表的 `quotation_count` 都对客户排除草稿 |
| `customer-portal/src/pages/MyQuotations.tsx` | 改注释 | 前端那行 filter 保留作双保险，注释写明真正的边界在后端 |

## 关联影响

1. **`loadQuotationWithAccessCheck` 是共用的**，除详情外还被 accept / reject /
   pending / versions 用到。客户对草稿做决策现在统一回 404「报价不存在」，
   而不是走到 service 层再报「报价当前状态为 DRAFT，仅…可以确认」——
   后者会把状态泄露出去。业务上没有回退：`applyClientDecision` 本来就只允许
   SENT / PENDING_DECISION，草稿从来就不能被接受。
2. **运营端完全不受影响**：所有过滤都只在 `userType === 'CLIENT'` 时追加，
   已实测运营仍能在列表、详情、版本列表、询价详情里看到草稿。
3. **询价列表的 `quotation_count`** 客户看到的数会比运营少（少掉草稿数）。
   这是有意的：报价还没发出来就告诉客户"已有 1 版报价"本身就是误导。
4. **跨模块 import**：`inquiry/routes.js` 引入了 `quotation/service.js` 的常量。
   属于后端运营侧模块之间的复用，项目里已有先例
   （quotation/service.js → order/service.js 等），不违反子系统隔离规范。
5. **确认不受影响**：开放 API（`open-api/service.js`、`webhook-service.js`）
   本来就写死了 `status NOT IN ('DRAFT','CANCELLED')` / `status IN ('SENT',...)`；
   报价邮件确认链接（quotation-response）走 token + `applyClientDecision` 状态守卫；
   承运商门户从来就拿不到报价（`loadQuotationWithAccessCheck` 对 CARRIER 直接 403）。
6. **无数据库改动、无权限码改动**，不需要迁移脚本，也不用跑权限同步校验。

## 验证

本地 `germany_box_transport`（localhost），在本 worktree 起后端（3098 端口，
已核对进程 cwd）跑脚本化验证：临时插入同一客户、同一线路、同一询价下的
一张 DRAFT + 一张 SENT 测试报价，用直接签发的客户 / 运营 JWT 打接口，
覆盖 6 组共 16 项断言，全部通过；测试数据跑完即删，库已恢复原样。

关键几项：

- 客户列表：返回 2 条且无 DRAFT，`pagination.total` 同步为 2（count 走同一段 SQL）
- 客户显式 `?status=DRAFT`：返回空
- 客户读草稿详情：404「报价不存在」，响应体里搜不到金额
- 客户读草稿版本列表 / 询价详情子列表：均无 DRAFT
- 客户 accept 草稿：404「报价不存在」
- 运营对应的 4 项：草稿照常可见

另做对照实验：把 `CLIENT_HIDDEN_STATUSES` 临时改成 `[]` 重启，
上述断言中的 6 项转为失败（客户拿到 DRAFT 与 9999.99 的金额），
确认修的是真问题而不是防御性代码。

## 注意事项

- `<> ALL($n::text[])` 的 `::text[]` 不能省，node-pg 传数组是 unknown 类型。
- 询价列表里那个占位符在 SELECT 子查询中，**必须先于所有 WHERE 条件 push**，
  否则参数错位。代码里已就近写了注释。
