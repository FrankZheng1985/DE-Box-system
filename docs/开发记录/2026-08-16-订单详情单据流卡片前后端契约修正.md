# 2026-08-16 订单详情「单据流」卡片前后端契约修正

**模块**：ERP 内核 —— 单据流引擎；订单模块（运营管理端详情页）

---

## 问题

订单详情页的「关联单据 / 单据流」卡片，单据类型徽章和单号都是空白，
金额也完全看不到 —— 尽管当天早些时候刚修完踩坑 017，库里的
`document_flow.amount` 已经确认写进去了。

## 根因

前后端字段名完全对不上，外加库里本来就缺展示所需的数据。详见
`docs/踩坑经验库/066_接口原样透传数据库行前端却按自造的字段名读.md`。

要点：

1. 后端 `getFullDocumentFlow()` 是 `SELECT * FROM flow`，透传 `document_flow` 的
   snake_case 列；前端 `LinkedDocument` 却手写成 `{ id, type, doc_number }`，
   三个字段全是 `undefined`，且每一层失败都不报错。
2. `document_flow` 表里**只有凭证 UUID，没有单号** —— 「显示单据类型 + 单号」
   这个需求光改前端做不到，必须后端补 JOIN。
3. `preceding_doc_id` 是 `documents.id`（凭证主键），而 `/orders/:id`、`/quotes/:id`
   这些详情页路由吃的是业务表主键。原代码把凭证 id 拿去拼 `/orders/${doc.id}`，
   口径本来就是错的。

## 改动

### 后端

`server/core/document-flow.js`

- 递归 CTE 补 `df.id AS flow_id`（前端当 React key 用）。
- 新增模块级函数 `farSideColumns(side)`，生成两个查询共用的 SELECT 片段：
  - `LEFT JOIN documents` 取 `doc_number` / `doc_type` / `doc_status`。
    **必须 LEFT** —— 上游凭证被删过会留悬空引用（踩坑 061），内连接会让整行消失。
  - `entity_id`：按凭证类型解析出对应业务单据主键
    （ORD→orders、QUO→quotations、INQ→inquiries、CMR→cmr_documents、
    FI_AR/FI_AP→financial_records），前端跳详情页用这个。
  - `doc_id` / `doc_type` 统一指「对端凭证」，前序查询取 preceding 侧，
    后续查询取 subsequent 侧，前端两边共用一套渲染逻辑。
- 原有字段（`preceding_*` / `subsequent_*` / `flow_type` / `amount` / `currency` / `depth`）
  **全部保留**，只做加法，`server/scripts/test-erp-core.js` 里按
  `preceding_doc_type` 断言的测试不受影响。

`server/modules/order/controller.js`

- 单据流改为**只给运营端返回**（`req.user.userType === 'OPERATOR'`）。
  原因见下方「顺带修掉的数据泄露」。

### 前端

`admin/src/pages/OrderDetail.tsx`

- `LinkedDocument` 接口按后端实际返回逐字段重写，全 snake_case，
  每个字段都注明来源和用途。
- 新增 `DOC_TYPE_LABEL_KEY`：凭证类型码（`ORD` / `QUO` / `INQ` / `CMR` /
  `FI_AR` / `FI_AP` / `FI_REC` / `FI_PAY` / `FI_REV`）→ 语言包语义 key。
  原来的 `docTypeLabelKey()` 直接把类型 `toLowerCase()` 当 key 用，
  是按「后端给小写」这个错误假设写的。
- `getDocTypeBadgeClass()` 的映射表同步换成凭证类型码。
- 新增 `docFlowRoute()`：有详情页的跳详情（用 `entity_id`），
  其余跳列表页，都匹配不上就**不给跳**（原来是 `navigate('#')`）。
- `DocFlowItem` 加金额展示：右对齐 + `tabular-nums`，走 `formatMoney()`
  （`amount` 是 NUMERIC，pg 驱动回字符串，`formatMoney` 内部 `parseFloat`）。
  金额为 null 时不占位。
- `doc_number` 为 null（凭证已被删）时显示「单据已不存在」，用灰色斜体区分，
  不再是一片空白。
- React key 从 `doc.id`（undefined）改成 `doc.flow_id`。

`admin/src/i18n/locales/{zh,en,de}.json`

- `docType` 段补 6 个 key：`inquiry` / `receivable` / `payable` / `receipt` /
  `payment` / `reversal`。
  原有的 `order` / `quotation` / `cmr` / `invoice` / `customs` / `release`
  **保留不动** —— `docType.order` 还被 CMRManagement、CustomsManagement、
  QuotationManagement、ShippingRelease 四个页面当通用「订单」标签用。
- `orderDetail` 段补 `docMissing`。

## 顺带修掉的数据泄露

`/api/v1/orders/:id` 对客户门户和承运商门户账号是开放的（`canAccessOrder` 只校验
订单归属）。而单据流里挂着 `FI_AP` —— **付给承运商的成本价**。
客户拿自己的 token 直接请求这个接口，就能看到我们的进价。

这个泄露是既有的（`amount` / `currency` 本来就在返回里），但本次改动把单号和
跳转 id 也补了进去，等于把它变得更好用，所以一并堵掉：

```js
if (order.document_id && req.user?.userType === 'OPERATOR') {
  flow = await documentEngine.getDocumentFlow(client, order.document_id)
}
```

**对现有功能零影响**：三个门户都没有渲染单据流，
`customer-portal` / `carrier-portal` 里根本没调用 `/orders/:id`
（只调 `/orders/:id/files`）。将来门户要开放这块，得按凭证类型逐条过滤，
不能整包丢过去。
