# 2026-08-06 · CI 健康检查改为真能失败

> 模块：CI/CD
> 承接：`2026-08-06-lint接入CI.md` 第四节记的遗留项，Frank 拍板本次做掉。

---

## 一、原来有两个毛病，叠在一起让这一步彻底失去意义

```bash
sleep 5
HTTP_STATUS=$(curl -s -o /dev/null -w "%{http_code}" http://${SERVER_HOST}/api/health || echo "000")
if [ "$HTTP_STATUS" = "200" ]; then
  echo "健康检查通过 (HTTP $HTTP_STATUS)"
else
  echo "警告: 健康检查返回 HTTP $HTTP_STATUS（可能服务还在启动中）"
fi
```

### 毛病 1：两个分支都不 exit 非 0

服务起不来它也照样绿。「CI 全绿」根本不能证明生产是活的
——这是踩坑 042「CI 状态 ≠ 生产状态」的另一面。

### 毛病 2（**更要命**）：探的地址一直是 301

`http://47.83.241.117/api/health` 自 2026-08-02 启用 HTTPS 强制跳转后，
**一直返回 301 而不是 200**。也就是说这一步**每次部署都在打印
「警告: 健康检查返回 HTTP 301」**，只因为它从不失败，没有任何人发现。

> ⚠️ 这两条叠加出一个陷阱：**如果只把 `if` 改成 `exit 1`，
> 每一次部署都会立刻开始失败**。地址必须同时修。
> 本次是先实测了端点行为才动手，不是照着代码想当然改。

实测三种写法（生产正常时）：

| 写法 | 结果 |
|---|---|
| `curl http://IP/api/health`（原来的） | **301** |
| `curl -L -k http://IP/api/health` | 200 + 正确 JSON |
| `curl https://kalunasped.com/api/health` | 200 + 正确 JSON |

## 二、改法

### 校验响应体，不只看状态码

nginx 返回一个陈旧页面同样是 200，证明不了 Node 应用还活着。
现在要求 body 里含 `"status":"ok"`：

```bash
probe() { curl -sS -k -L -m 15 "$1" 2>/dev/null | grep -q '"status":"ok"'; }
```

### 退避重试，而不是 sleep 一个拍脑袋的固定值

PM2 reload 是渐进式的，新旧进程交替期间可能短暂不可用。
源站退避 `0,3,5,8,12,15,15,15`（累计约 75 秒），域名 `0,3,5,8,12`。

### 探两个地址，都是硬失败

| 地址 | 意义 |
|---|---|
| `https://<IP>/api/health`（`-k`） | 源站直连，绕开 DNS/CDN，**部署这一步真正控制的东西** |
| `https://kalunasped.com/api/health` | 用户实际走的路径；打不开 = 客户打不开，一样严重 |

两段的报错分别指向不同排查方向（源站坏 vs DNS/证书/nginx 域名块坏）。

## 三、⚠️ 它是报警器，不是保险丝

这一步失败**不会自动回滚**——到这里 rsync 和 PM2 重启都已经做完了。
红了只说明「生产可能已经坏了，要人立刻去看」。
真正的自动回滚是另一个量级的工程（要留旧版本、要能一键切回），**本次不做**。

## 四、验证（正例 + 两个反例 + 一个兼容性）

脚本是从 yml 里**原样抽出来跑的**，不是另写一份差不多的：

| 用例 | 预期 | 实际 |
|---|---|---|
| 生产正常 | 退出 0 | ✔ 退出 0，源站与域名均第 1 次尝试即通过 |
| **地址返回 200 但 body 不对**（探首页） | 退出 1 | ✔ 退出 1，重试耗尽后报错 —— 证明 body 校验真的在起作用 |
| 地址完全不可达（`127.0.0.1:9`） | 退出 1 | ✔ 退出 1 |
| 外层套 `set -e` | 不误中断 | ✔ 退出 0 |

> 最后一条是特意测的：原写法里的 `[ "$wait" -gt 0 ] && sleep "$wait"`
> 在 `wait=0` 时整条返回非 0，将来若有人给这个 run 块加 `set -e`
> 会在第一次循环就误中断。已改成 `if ... then ... fi`，并在注释里写明原因。

## 六、关联影响

- **不影响部署本身**：这一步在最后，前面 rsync/PM2 全部照旧。
- **今后若真失败**：先看报错指向源站还是域名，再按对应方向排查；
  **不要**为了让 CI 变绿把这一步改回不阻断——那等于退回今天之前的状态。
- 与本轮先做的「lint 接入 CI」是两件事：lint 在**部署前**拦不合规代码，
  健康检查在**部署后**确认生产还活着。一前一后。
