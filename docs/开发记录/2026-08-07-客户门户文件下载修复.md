# 2026-08-07 三端文件下载修复

> 模块：客户门户 + 运营管理端 + 承运商门户（订单文件 / CMR）+ 后端 order / cmr 模块

## 问题

客户在客户门户点"下载"（后台上传的装车图、CMR 文件、签收凭证），到了下载界面点了没反应，
文件下不来。排查中发现运营端和承运商门户是**同一个坏法**，Frank 确认后一并修掉。

## 根因

库里 `file_url` 存的是阿里云 OSS 的 **http:// 直链**，而门户跑在 https 上：

1. Chrome 会把"https 页面发起的 http 下载"当作不安全下载**静默拦掉**；
2. `<a download>` 这个属性**对跨域地址无效**，就算换成 https 也只是新标签页打开，不是另存为；
3. 附带问题：直链不带鉴权 + bucket 公共读，等于客户单据对全网公开。

详见 `docs/踩坑经验库/052_把OSS的http直链交给前端下载会被浏览器当不安全下载拦掉.md`。

## 方案

后端加代理下载接口，前端一律走它：同源、https、带 JWT 鉴权、
`Content-Disposition` 由后端控制。文件仍然存在 OSS，只是由后端转一手。

## 关联影响

**一并处理的：**

- `GET /cmr/:id`（CMR 详情）原来**没有租户校验**——客户拿着别家的 CMR id 就能读到详情
  （踩坑 016 / 023 同族）。下载接口要用同一套校验，顺手把详情也补上了。
  查不到和无权访问都回 404（回 403 等于告诉对方这个 UUID 是有效记录）。
  校验用的 `client_id` / `carrier_id` 已从对外响应里剔除，详情的返回字段和原来一致。

- `sendStoredFile` 的本地回退根目录改成可用 `UPLOAD_ROOT` 环境变量覆盖，
  默认仍是生产的 `/var/www/germany-box-system/uploads`。**生产行为不变**，
  只是让开发机（没有 /var/www 写权限）能验证这条分支。

**受影响但本次没改的：**

- 上传逻辑（`POST /orders/:id/files`、`POST /cmr/upload`）**没动**，
  库里存量的 http 直链也**没有做数据迁移**——下载不再依赖它，
  `ossPathFromUrl()` 能从这些老 URL 里把 OSS key 反推出来。

**确认不受影响的：**

- 订单文件列表 `GET /orders/:id/files` 返回结构没变，仍然带 `file_url`（其他端还在用）。
- 新路由是三段路径 `/files/:fileId/download`，不会和 `/:id`、`/:id/files` 抢匹配；
  `/cmr/:id/download` 是两段，同样不影响 `/cmr/:id`。
- 上传、删除、签署状态、货损标记等接口一律没动。

## 部署顺序（硬依赖）

**必须先后端后前端**，反了的话前端调的接口还不存在，下载会回 404。

1. 后端：上传 `server/utils/file-response.js`、`server/utils/oss-service.js`、
   `server/modules/order/routes.js`、`server/modules/cmr/routes.js`，
   然后 `pm2 delete all && pm2 start`
2. 前端：三端各自 `npm run build`，清旧资源后上传 dist
   （`customer-portal` / `admin` / `carrier-portal`）

没有数据库迁移，不需要备份 RDS。
