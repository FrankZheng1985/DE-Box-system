## 一、意见 #13：客户端「我的报价」看不了订单详情

### 需求

苏凌 2026-08-28 提，优先级「紧急」。客户门户「我的报价」列表里，
已下单的报价虽然在报价单号下面显示了关联订单号，但点不动、操作列是 `—`，
客户看不了这张订单。要求加一个眼睛入口，并且双击订单号也能进详情。

### 做法

订单详情页（`/orders/:id`）在意见 #11 时已经上线，缺的只是入口。
后端也不用改：报价列表 SQL 是 `SELECT q.*`，`converted_order_id`
本来就随着返回（只有 `carrier_cost` 两个成本字段会在出口被剥离），
前端此前没有声明这个字段而已。

| 改动 | 说明 |
|------|------|
| 操作列 | 有 `converted_order_id` 时显示「查看」（Eye 图标）→ `navigate('/orders/:id')`；与既有的接受/待定/拒绝按钮共存于同一个 flex 容器 |
| 订单号 | 加 `onDoubleClick` 跳转 + `cursor-pointer hover:underline` + title 提示「双击订单号查看订单详情」；拿不到 id 时保持纯文本，不给一个点不动的手型光标 |

## 二、意见 #14：订单履约全过程线上可视化

### 需求

同日同人提，优先级「紧急」。附件箭头指向管理端订单详情页的「订单时间线」区域。
原文要求的链路：

1. 运营在已确认订单下写一条要传达给客户的履约信息
2. **系统自动发到客户指定的微信群**
3. 同时在客户端订单日志里生成一条记录
4. 客户查看后标记已读，已读回传后台
5. 客户可以在该条信息下直接回复处理意见，意见回传后台

### 口径（Frank 2026-08-28 拍板）

- **微信群推送本次不做**。个人微信群没有官方发送接口，技术上只有企业微信群机器人
  webhook 可行，而客户（翼能）用的是什么群还没确认。本次先做站内信 + 邮件，
  代码里把发通知收敛在 `sendOrderMessageNotification()` 一个函数里，
  将来接微信只在那里加一路出口，**不用动表结构**。
  所以迁移里也**没有**预留 webhook 字段——没确认的外部协议先不进库。
- 「已经确认的订单」= 排除卡车 `PENDING_REVIEW`、本地派送 `PENDING_QUOTE`、
  以及 `CANCELLED`，其余状态放行。
- 已读是**手动点按钮**，不是打开页面就算读过——回执要有意义。
- 结构只做两层（主消息 + 回复），不做无限层级。

### 数据模型（迁移 135）

| 表 | 说明 |
|----|------|
| `order_messages` | 主消息与回复共用一张表，`parent_id` 为 NULL 即主消息；`sender_type` 只有 OPERATOR/CLIENT（带 CHECK 约束） |
| `order_message_reads` | 已读回执，主键 `(message_id, user_id)` 天然幂等。单独一张表是因为一家客户可能有多个门户账号，「谁在什么时候读的」运营侧要能逐条看到 |

新增两个权限码：`order:message`（运营发布/查看）、`portal:order_message`（客户查看/已读/回复）。
授权口径跟着既有权限推导：有 `order:status` 的角色拿运营侧，有 `portal:order_view`
的角色拿客户侧，sys_admin / boss 一并补上。

### 后端端点（全部在 `server/modules/order/message-routes.js`）

| 端点 | 谁能调 | 说明 |
|------|--------|------|
| `GET /orders/:id/messages` | 运营 + 客户 | 返回「主消息 + replies + reads」两层结构 |
| `POST /orders/:id/messages` | 仅运营 | 发布履约信息，带状态守卫 |
| `POST /orders/:id/messages/:messageId/replies` | 运营 + 客户 | 回复，只能挂在本订单的主消息下 |
| `POST /orders/:id/messages/:messageId/read` | 运营 + 客户 | 标记已读，幂等 |

**租户与字段隔离**（踩坑 069 的规矩）：

- 每个端点各自做一遍校验，不靠「隔壁接口做过了」
- 承运商一律按「订单不存在」处理——履约沟通只在运营 ↔ 客户之间
- 不属于自己的订单回 **404 不是 403**
- 非 UUID 的 id 先被正则挡掉，不扔给 pg 变成 500

**通知**：

- 运营发布 / 运营回复 → 通知该客户全部在职门户账号，`channel: 'BOTH'`
  （强制站内 + 邮件：这条链路是拿来替代微信群的，客户没看到就等于没送达；
  用户没邮箱时通知引擎自己退回纯站内信）
- 客户回复 → 通知全体在职运营（默认渠道，站内）
- 客户标记已读**不发通知**（后台看回执即可，避免噪音）
- 通知在写库之后独立发送，失败只 `console.warn` 不抛回前端（同 a530c07 的套路）

## 上线注意
