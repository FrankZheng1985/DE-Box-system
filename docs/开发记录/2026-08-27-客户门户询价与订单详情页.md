# 2026-08-27 客户门户：询价详情页 + 订单详情页

> 模块：客户门户（customer-portal）+ 订单（order）+ 询价（inquiry）
> 来源：飞书《EU-TMS 开发意见表》第 11 条（苏凌，2026-08-18 提，优先级「紧急」）
> 本次只做第 1 批（查看详情）；第 12 条「修改功能」未做，见文末。

---

## 需求原文

> **现状描述**：目前客户端无论是询价还是订单，都无法查看订单详情
> **期望效果**：客户端无论是建立的询价单还是订单，都可以查看订单详情，
> 包含地址信息，货物尺寸重量等基本信息。方便操作人员核对订单信息。

附件截图指向客户门户「询价」列表：询价编号不可点击，操作列只有一个删除图标。

---

## 做了什么

### 一、先堵一个现存的数据泄露（做详情页的前置）

做详情页 = 把订单接口的响应渲染出来。渲染之前必须确认响应里没有不该给客户的东西 ——
一查发现 `GET /orders` 和 `GET /orders/:id` 一直在把 **`carrier_cost`（承运商成本价）**
发给客户门户，`GET /orders/:id/timeline` 则**完全没有租户校验**。

详见 `docs/踩坑经验库/069_门户接口按o星号透传把承运商成本价发给了客户.md`。

处置：新增 `server/modules/order/portal-view.js` 按登录身份做**字段白名单**，
list / getById / getTimeline 三个出口统一过一遍；timeline 补租户校验 + UUID 守卫。

### 二、客户门户新增两个详情页

| 页面 | 路由 | 取数 |
|------|------|------|
| 询价详情 | `/customer/inquiry/:id` | `GET /inquiries/:id`（已有接口，无需改动） |
| 订单详情 | `/customer/orders/:id` | `GET /orders/:id` + `GET /orders/:id/timeline` |

**询价详情**展示：基本信息（编号/客户单号/服务类型/运输方式/车型/柜号）、
取件与派送地址+两侧联系人、货物汇总、**按件明细（件号/描述/件数/长/宽/高/单件重/体积/LDM）**、
本地派送三层结构下按票分组展示各票的地址与件明细、已收到的报价列表（草稿由后端过滤）。

**订单详情**展示：基本信息、装卸货地址+联系人、货物信息、集装箱与航运信息（仅整柜单）、
时间安排、**状态变更时间线**（已脱敏，不含内部员工姓名和内部备注）。

入口一共四个：询价编号可点、询价列表操作列「查看」按钮、订单号可点、
订单列表操作列「查看」按钮；概览页「最近订单」那一行本来就是 `cursor-pointer`
却只跳回列表，现在直接进这张单的详情。

## 关联影响分析

**一并改了的：**
- 承运商门户也走同一批订单接口，白名单一并覆盖：它现在拿不到 `client_price`（我们的售价）。
  已核对 `carrier-portal` 只用 `id / order_number / pickup_city / delivery_city /
  business_type / cargo_weight_kg / status / created_at`，全在白名单内，**功能不受影响**。
- 客户门户 `Tracking.tsx` 显示 `carrier_name`，是既有业务口径，白名单保留了这个字段。
  它走的是 `/gps/active` 不是 `/orders`，本次改动碰不到它。
- 客户门户「我的订单」列表读 `client_price`，在白名单内，**显示不变**。

**确认不受影响的：**
- 运营管理端（`userType === 'OPERATOR'`）原样返回全部字段，`scrubOrder` 直接 return row，
  订单列表 / 详情 / 导出 一个字段都没少。
- 询价模块**没有改任何返回内容**：`inquiries` 表本身不含成本类字段，
  草稿报价过滤后端早已实现（踩坑 054），本次只补了一个 UUID 守卫。
- 权限体系**不需要动**：两个详情页复用已有的 `portal:order_view` / `portal:inquiry_manage`，
  没有新菜单、没有新权限码，因此不涉及「权限四件套」，也**没有数据库迁移**。

**没做但相关的：**
- 订单详情页**不放文件列表** —— 文件入口留在列表页的文件弹窗里，避免同一套下载逻辑写两遍。
- 订单没有按件明细表（`order_items` 是 V1 遗留、代码里已无人使用），
  所以订单详情的货物是汇总口径（描述/件数/总重/总体积）；
  **按件的长宽高只有询价侧有**，在询价详情页完整展示。

## 未做：飞书第 12 条「修改功能」

第 12 条（2026-08-27 提，优先级「高」）要求客户端能修改未报价的询价单和订单，
且「已获得报价时要能退回待报价状态」。核查结论：

- 询价编辑 `PUT /inquiries/:id` 已支持客户门户且已有「仅 PENDING_QUOTE 可编辑」守卫，
  **后端不用动，只差前端按钮**；
- 订单编辑 `PUT /orders/:id` 是 `requireUserType('OPERATOR')`，客户门户调不了，
  需要新开门户编辑路径 + 新权限码 `portal:order_edit`（**要写迁移**）；
- 「重新变成待报价状态」**目前不存在这条路径** —— 客户拒绝报价走
  `POST /quotations/:id/reject`，结果是询价变 `REJECTED` 而不是 `PENDING_QUOTE`。
  这是逆向状态流转，已发出的报价怎么处置（建议作废 VOID 并保留历史版本）需业务侧拍板。
