### nginx 安全响应头

新增 `/etc/nginx/snippets/eutms-security-headers.conf`，
在 5 个静态 location（`/admin`、`/customer`、`/carrier`、`= /`、`/`）里 include。
仓库内留了一份副本：`deploy/nginx-eutms-security-headers.conf`。

**绕开的两个坑**：

1. **add_header 继承陷阱**：nginx 里子 location 只要出现一个 add_header，
   父级的全部 add_header 都会失效。`location = /` 本来就有 `Cache-Control`，
   若把安全头写在 server 级，官网首页的安全头会全部不生效。
   所以逐个 location include，而不是 server 级写一遍。
2. **不给 `/api` 加**：Express 的 securityHeaders 已经加过同名头，
   nginx 再加会出现重复头（X-Frame-Options 出现两次时浏览器行为未定义）。
   实测 API 侧仍只有一个 `x-frame-options: DENY`。

**加了什么**：

| 头 | 值 | 说明 |
|---|---|---|
| X-Frame-Options | `SAMEORIGIN` | 用 SAMEORIGIN 不用 DENY：外部嵌套一样挡住，不误伤同源内嵌 |
| X-Content-Type-Options | `nosniff` | |
| Referrer-Policy | `strict-origin-when-cross-origin` | 路径里可能有订单号，跨站只带 origin |
| Permissions-Policy | 关掉 geolocation/microphone/camera/payment | |
| Strict-Transport-Security | `max-age=300` | **先 5 分钟观察**，见下 |

**刻意没做的两件事**：

- **HSTS 只给了 300 秒**。一旦浏览器记住 HSTS，在 max-age 内该域名只能走 HTTPS，
  证书出问题时用户连"继续访问"都点不了。观察一两天确认证书续期与访问正常后，
  再逐步调到 `31536000`（一年）。**不加 `includeSubDomains` 和 `preload`**——
  那两个一旦被浏览器或预加载列表记住极难撤回。
  （HSTS 按域名生效，IP 直访 `https://47.83.241.117` 那条应急回退不受影响。）
- **没加 CSP**。GPS 追踪页从 unpkg CDN 加载 Leaflet，SPA 也有内联样式，
  贸然上 CSP 会直接打破功能，需要单独做一轮梳理。
