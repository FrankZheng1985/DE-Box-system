# 2026-08-07 · 编号分配器（治并行对话撞号）

> 模块：仓库工具
> 承接：踩坑 042 点了「并行对话会撞踩坑编号」但没给解法，之后又撞了一次。

---

## 一、问题有多实在

截至今天，**踩坑编号已经撞了四次**：

| 号 | 两篇分别是 |
|---|---|
| 030 | 屏蔽 readline 回显 / 认证中间件让新路由看起来一样 |
| 036 | 筛选 Tab 用小写 key / 角色留空建出的账号处处 403 |
| 041 | Excel 校对表回收 / 认证密钥兜底默认值 |
| 050 | rsync --delete 静默删文件 / 抽组件后残留 import（这次靠改名 051 躲过，多花一个提交） |

**顺带查出迁移也撞过一次**：`005_add_business_type.sql` 与
`005_order_status_enhancement.sql`。两个都是 V1 时代的老文件（V2 从 100 重建），
现在不影响执行，但**迁移撞号比文档撞号严重得多**——迁移是按顺序跑的。

## 二、为什么"看目录最大号 +1"必然失败

因为**别的对话的活正躺在它自己的 worktree 里，还没推上来**。

- 只看自己工作区 → 看不到别人的
- 只看 `origin/main` → 同样看不到别人**没推**的

两个对话同时看到 050，就会同时写 050。

## 三、做法

新增 `scripts/next-numbers.js`（`npm run next:num`），**三处都扫**：

1. `origin/main`（已上线的）
2. 当前工作区（自己刚写的，含未提交）
3. **所有兄弟 worktree**（别的对话正在写、还没推的）← 这条才是关键

同时管两类编号：`docs/踩坑经验库/` 和 `server/database/migrations/`。
退出码 0 = 无撞号，2 = 发现重复。

### 两个实现上的坑（都踩过并修了）

1. **同一个文件出现在多处不是撞号**。一开始按「编号 → 来源集合」判重，
   于是同一份文件同时出现在 origin/main、本工作区和三个 worktree 里
   就被当成"5 个冲突"，**每一个号都报红**。
   改成「编号 → **文件名** → 来源」，只有同号对应**不同文件名**才算撞。
2. **`git ls-tree` 会把中文名转义**成 `\350\267\257` 之类，和本地文件名对不上，
   导致 origin/main 那一路全部漏检。要加 `-c core.quotePath=false`。

### 一个已知的假阳性

兄弟 worktree 若停在较早的提交上，会留着**已被改名的旧文件**，从而报出假撞号
（本次 legal-pages 落后一个提交，仍有改名前的 `050_抽公共组件…`）。
脚本在检出撞号时会打印提示：**先看它是不是只出现在某一个 worktree 里**。

宁可多报也不漏报——漏报的代价是撞号真的落到 main 上。

## 四、⚠️ 它降低概率，不能根除

两个对话在同一秒跑它，仍会拿到同一个号。真正根除要加锁，而多对话之间没有共享锁。

所以配套纪律没变，反而更要紧：**取到号后尽快提交推送，别攒着**。

## 五、修改文件

| 文件 | 操作 |
|---|---|
| `scripts/next-numbers.js` | 新增 |

| `docs/开发记录/交接-下次开发从这里开始.md` | 开工检查清单里加这一步 |

## 六、未做

**没有给已撞号的 4+1 处重新编号。** 改号会破坏其他文档里的交叉引用
（"见踩坑 036"会变得指向不明），收益小于风险。
现有撞号就让脚本每次都报出来，提醒大家它们存在。
