# 2026-08-06 三端 401 后自动跳回登录页

## 背景

踩坑 043 把无效令牌的响应从 403 改回 401 后，前端能正确清掉本地登录态了，
但**只清不跳**：用户停留在一个"侧边栏还在、数据全空、控制台一堆 401"的页面上，
必须手动刷新才会被路由守卫送回登录页。当天 JWT 密钥轮换（全员登出事件），
Frank 本人就卡在这个状态里以为系统坏了。

## 修改内容

三端 `api.ts` 的 401 分支，在清掉 localStorage 后整页跳转回各自的登录页；
已在登录页上时不跳，避免循环。

```ts
if (response.status === 401) {
  localStorage.removeItem(AUTH_STORAGE_KEY)
  if (window.location.pathname !== '/login') {   // 各端换成自己的登录路径
    window.location.href = '/login'
  }
  throw new ApiError(i18n.t('apiError.sessionExpired'), 401, 'UNAUTHORIZED')
}
```

用整页跳转（`window.location.href`）而不是路由 `navigate`，是刻意的：
api.ts 不在 React 组件树里拿不到 router；且整页刷新能把 AuthContext 等
内存态一并清干净，避免"storage 清了、内存态还认为已登录"的半残状态。

## 关联影响

- **登录页自身的报错不受影响**：登录接口失败返回的是 HTTP 200 + body `code:401`
  （`res.json` 不带 `.status()`），不会进 `response.status === 401` 分支，
  「用户名或密码错误」仍在登录页内联显示。
- **三个登录路径都带各自 basename**（customer/carrier 的 `window.location.pathname`
  含 `/customer` `/carrier` 前缀），生产 nginx 与本地 vite dev 行为一致。
- 后端零改动；语言包零改动（沿用 `apiError.sessionExpired`）。

## 验证

- 三端 `npm run build` 通过、四包 lint 通过（0 错误，警告为既有基线）。
- 本地实测（worktree 起 vite 5199 + 只回 401 的桩后端占 3002）：
  伪造坏令牌进 `/dashboard` → 接口 401 → localStorage 清空 → 自动落在 `/login`，
  登录页渲染正常、无刷新循环。
- 生产部署后用同样手法复测（见部署段）。
