# 2026-08-07 修 `/admin/` 子路径入口显示「页面不存在」

**模块**：运维 / nginx / 管理端路由
**触发**：Frank 打开 `https://kalunasped.com/admin/`，侧边栏和登录态都正常，内容区却显示「页面不存在」

---

## 问题说明

管理端 SPA 部署在**根路径**（`admin/vite.config.ts` 是 `base:'/'`，`App.tsx`
的路由全是 `/dashboard`、`/orders` 这类无前缀路径，`BrowserRouter` 没设 `basename`），
但 nginx 里额外挂了一个 `/admin/` 的 alias 块返回同一份 `index.html`。

结果访问 `/admin/`：nginx 返回 200 → 资源在 `/assets/` 也能拿到 → SPA 正常启动 →
Layout 把侧边栏顶栏全渲染出来，但 React Router 拿 `/admin/` 匹配不到任何 Route，
内容区落到兜底 `<Route path="*" element={<NotFound />} />`。

即「外壳对、内容 404」，nginx 日志和前端 console 都干净，没有任何一环报错。
`/admin/` 这个入口从上线起就没生效过——是当初打算子路径部署、后来改根路径时
nginx 侧没清掉的残留。

---

## 修改文件

| 文件 | 操作 | 说明 |
|------|------|------|
| `deploy/nginx-eutms-app.conf` | 修改 | `/admin` 的 alias 块改成 301：`= /admin` 与 `= /admin/` → `/dashboard`，`location /admin/` 用 `rewrite ^/admin/(.*)$ /$1 permanent` 去前缀；附上原因注释 |
| `/etc/nginx/snippets/eutms-app.conf`（线上，非仓库） | 同步 | scp 覆盖 + `nginx -t` + `systemctl reload nginx`；备份 `eutms-app.conf.bak-20260807-212003` |
| `.claude/CLAUDE.md` | 修改 | 「Nginx 路由规则」原写 `/admin/ → 管理端 SPA`（错的），改为 301 说明，并加「管理端没有 /admin 前缀，要加得同时改 vite base + Router basename」的警告 |
| `docs/踩坑经验库/058_给根路径部署的SPA挂子路径alias导致外壳正常内容404.md` | 新增 | 完整踩坑记录 |

**前端代码零改动**，不需要重新构建、不需要重新部署 admin/dist。

---

## 为什么不是删掉那个 location

删掉后 `/admin/` 会落到最后的 `location /`，照样返回 index.html，
前端照样匹配不到路由，还是显示「页面不存在」。SPA 的兜底路由会把
「路径不存在」伪装成「页面不存在」，所以必须显式重定向。
