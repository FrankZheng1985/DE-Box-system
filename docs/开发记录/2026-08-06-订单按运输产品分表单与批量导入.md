# 2026-08-06 订单按运输产品分表单 + 批量导入

**模块**：订单（order） / 客户门户 / 运营管理端
**需求来源**：Frank —— 「新建订单应该是分运输产品，根据运输产品不同，产品字段应该也是不同。然后还需要有批量导入功能，能批量创建订单。」

---

## 一、做了什么

### 1. 客户门户建单页改成按运输产品分表单

改造前：客户门户三个产品共用一张表单，只有一个「服务类型」下拉框。
集装箱单要填的提单号 / 柜号 / 船公司 / ETA / 卸货港在门户**根本没有输入框**，
客户只能写进备注，运营再手工誊进系统。

改造后（与运营端 `OrderCreate.tsx` 的字段划分对齐）：

| 运输产品 | 表单分组 |
|---------|---------|
| 卡车派送 LTL | 基本信息（FTL/LTL）、装货地址、卸货地址、货物信息、时间安排、其他信息 |
| 卡车运输 FTL | 航运信息、集装箱信息、港口与配送、放单与清关、货物信息 |
| 本地派送 | 装货地址、卸货地址、货物信息、时间安排、其他信息（**没有运输类型**） |

必填项：LTL / 本地派送＝装卸货的国家和城市；FTL＝提单号、柜号、卸货港、最终目的地
（与导入模板的必填列一致）。

### 2. 批量导入（两端）

- **一行 = 一张订单**（订单没有按件明细子表，货物是 orders 上的四个聚合字段）
- **三个产品各一份模板**，列只包含该产品要填的字段
- 流程：选产品 →（运营端还要选客户）→ 下载模板 → 上传 → 预览校验 → 确认导入
- **预览和导入用同一个解析函数**，「预览看到几张，导进去就是几张」
- **有一条错误就整批不导**，避免导一半客户不知道该补哪几张
- 导入的订单和手工建单完全一样：走凭证引擎、进「待审核」、FTL 自动建清关/放单记录
- 单次上限 200 行、文件 5 MB

容错：三种语言的模板表头都认（德语同事下的模板中文同事能导）、认常见中文别名列头、
认德式数字（`1.200,5`）和德式日期（`01.09.2026`）、「电放/正本」「是/否」这类口语值也认。

### 3. 顺带修掉的两个既有缺陷

- **联系人字段静默丢失**：运营端建单页传的 `pickupContact` / `deliveryPhone` 等四个字段，
  后端从来没接收过（详见踩坑 047）。现在在 service 层并入地址 JSONB，三个入口一起修好。
- **客户门户建单没有强制租户隔离**：`POST /orders` 直接吃前端传的 `clientId`，
  客户门户账号改一下就能给别家公司造单。现在 CLIENT 身份一律用 JWT 的 `linkedEntityId`
  （和列表接口踩坑 016 / 023 同族）。已用伪造 clientId 实测确认拦住。
