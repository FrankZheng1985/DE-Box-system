# 042 · 并行对话会撞 CI 部署（PM2 抢锁）与踩坑编号

> 发现日期：2026-08-06
> 背景：Frank 常同时开多个 Claude Code 对话改同一个仓库，
> 全局 CLAUDE.md 已规定各自开 worktree——**但 worktree 隔离不了 CI 和生产**。

## 一、两次 CI 部署撞车，后一次直接失败

两个对话相隔 **8 秒**推 main，触发两条 Deploy to Production：

```
[PM2][ERROR] Reload already in progress, please try again in 28 seconds or use --force
##[error]Process completed with exit code 1.
```

前一条正在 `pm2 reload`，后一条挤进来被 PM2 拒绝，整个 job 红。

### 危险的地方：红 CI ≠ 生产是旧代码

这次的实际情况是**代码已经在生产跑着**，只是那一步失败了。因为 CI 的顺序是
「构建 → rsync 文件 → 装依赖 → 重启」，失败发生在**最后一步**，
文件早就 rsync 上去了；随后另一条部署的 reload 完成时，顺带把新文件也加载了。

**所以不能看见红就断言"没上线"，也不能看见红就慌忙重推。** 判断方法是
**比对文件落盘时间与进程启动时间**：

```bash
stat -c '%y  %n' /var/www/germany-box-system/server/modules/order/service.js
ps -o pid,lstart,cmd -p $(pgrep -f app.js) --no-headers
```

进程启动时间**晚于**文件落盘时间 → 新代码已加载。本次：
文件 `11:50:04`、进程 `11:51:56` → 已加载，无需补救。

反过来若进程更早，才需要真去重启。

## 二、踩坑编号也会撞

写本篇时发现仓库里**同时存在两个 041**（不同对话各写一篇，都推上去了，
git 不会报冲突因为文件名不同）。036 历史上也重过。

编号靠"看目录最大号 +1"在并行下**必然失效**——两个对话同时看到 040，
就会同时写 041。

## 三、防护规则

1. **推之前重新 `git fetch`，推完立刻看 Actions**。
   隔几分钟就要重看一次 `git log origin/main`——主线会在脚下动。
2. **CI 红先判断性质再动手**：是构建失败（代码问题，生产没变）
   还是部署步骤失败（可能已经上线了）。**用时间戳判断，别猜也别重推**。
3. **踩坑/迁移编号一律以 `origin/main` 为准现取现用**，
   而且**取完立刻提交推送**，别攒着——攒得越久越容易撞：
   ```bash
   git fetch origin
   git ls-tree -r --name-only origin/main -- docs/踩坑经验库/ | grep -oE '[0-9]{3}' | sort -n | tail -1
   ```
4. **文档里写死的数字（迁移号、样本数据、最新提交 hash）都会被别的对话作废**。
   写成自校正表述（"`ls` 看最大号 +1"）而不是写死的值。
   本次 `交接-下次开发从这里开始.md` 就因此三处过期：
   迁移号 121 被占、准时率样本随清库作废、派单页样本数据不存在了。
