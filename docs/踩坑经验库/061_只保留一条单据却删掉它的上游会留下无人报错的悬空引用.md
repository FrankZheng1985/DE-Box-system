# 061 · 只保留一条单据却删掉它的上游，会留下无人报错的悬空引用

## 问题现象

清理测试数据时，业务方给的清单是「订单删这 3 条、询价单和报价单全删」，
同时又要保留另一条订单。照着清单删完，系统看起来一切正常：
订单列表能打开、详情页能进、接口全部 200、门禁全绿。

但那条保留下来的订单，详情里的**「来源报价单」永远查不出来**，
单据流那一栏是空的——而后端日志里一条错误都没有。

## 根本原因

保留的订单 `EU-20260808-0004` 其实是从报价单转来的，完整链路是：

```
INQ-20260807-0004  →  QUO-20260808-0003  →  EU-20260808-0004
```

这条链在库里由两处记录：

| 位置 | 字段 | 有没有外键约束 |
|------|------|---------------|
| `documents` | `source_doc_type` / `source_doc_id` | **没有**（软引用） |
| `document_flow` | `preceding_doc_id` / `subsequent_doc_id` | **没有** |

`document_flow` 只有 `NOT NULL` 和一个 `UNIQUE(preceding_doc_id, subsequent_doc_id)`，
**没有任何 FOREIGN KEY 指向 documents**。所以删掉上游的 QUO 凭证时：

- 数据库不报错（没有外键要维护）
- `document_flow` 里那条 `QUO_TO_ORD` 记录照样留着，指向一个已经不存在的凭证
- `documents.source_doc_id` 也一样，指向空气

**这是典型的静默失败**：删的时候一声不吭，用的时候只是"查不到"，
不会抛异常、不会 500，等业务方哪天点进详情页问「怎么没有来源单据」才发现。

## 正确做法

**删业务单据前，先把要保留对象的上下游链路查出来，整条一起保留或整条一起删。**

查链路的两句 SQL：

```sql
-- 保留对象的上游是谁
SELECT * FROM document_flow WHERE subsequent_doc_id = '<保留对象的 document_id>';

-- 凭证自己记的来源
SELECT doc_number, source_doc_type, source_doc_id FROM documents WHERE id = '<同上>';
```

删完之后必须回头验一遍没有悬空引用（正常应该都是 0）：

```sql
SELECT count(*) FROM document_flow df
 WHERE NOT EXISTS (SELECT 1 FROM documents d WHERE d.id = df.preceding_doc_id)
    OR NOT EXISTS (SELECT 1 FROM documents d WHERE d.id = df.subsequent_doc_id);

SELECT count(*) FROM documents d
 WHERE d.source_doc_id IS NOT NULL
   AND NOT EXISTS (SELECT 1 FROM documents x WHERE x.id = d.source_doc_id);
```

如果业务上确实只能保留下游、上游必须删，那就**同时把 `document_flow` 那条记录和
`source_doc_id` 一起清掉**，让它干净地"没有来源"，而不是留个指向空气的指针。

## 防护规则

1. **单据清理的白名单，粒度是「链」不是「单」**。业务方给的清单往往只列他看得见的
   那一层（订单），上游的询价/报价他不会想到，得开发方自己查出来提醒。
2. **凡是没有外键约束的关联字段（软引用），删数据时都要手工兜**。这个库里
   `documents.source_doc_id`、`document_flow` 两处都是软引用，`change_documents.object_id`
   甚至是 varchar 存 UUID，同理。
3. **清理脚本收尾必须跑悬空引用检查**，不能只核对"保留的还在、该删的没了"——
   数量对得上，链断没断是另一回事。
