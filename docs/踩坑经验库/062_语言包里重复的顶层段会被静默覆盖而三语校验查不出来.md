# 062 语言包里重复的顶层段会被静默覆盖，而三语校验查不出来

## 问题现象

给客户门户询价页加「专车 / 拼车」选择时，往 `customer-portal/src/i18n/locales/*.json`
加了一个顶层段：

```json
"transportType": {
  "FTL": "专车",
  "LTL": "拼车"
}
```

三件事全是绿的：

- `npm run check:i18n` 通过，还报「三语各 742 个 key」完全一致
- `tsc --noEmit` 无报错
- `eslint` 无报错

但页面上那两个按钮显示的是 **「整车 (FTL)」「拼车 (LTL)」** —— 不是我写的文案。
乍看像是缓存没刷新、或者 i18next 没热更新，很容易往 vite 缓存、i18n 初始化上查。

## 根本原因

这个文件里**本来就有一个 `transportType` 顶层段**（在 300 行开外，给订单表单用的，
带 FCL / LCL 四个值）。我加的那份在 171 行，两段同名：

```json
{
  "transportType": { "FTL": "专车", "LTL": "拼车" },              ← 我加的，在前
  ...
  "transportType": { "FTL": "整车 (FTL)", "LTL": "拼车 (LTL)",
                     "FCL": "整箱 (FCL)", "LCL": "拼箱 (LCL)" }   ← 原有的，在后
}
```

**JSON 规范允许重复键，解析器取最后一个** —— `JSON.parse` 不抛错、不警告，
前面那份直接消失。所以「文案没生效」是必然的，而不是缓存问题。

更麻烦的是 **`scripts/check-i18n-keys.js` 结构上不可能发现它**：它先 `JSON.parse`
再比对三语的 key 集合。重复键在 parse 阶段就已经被合并掉了，脚本看到的是合并后的对象。
而且我在 zh / en / de **三份都加了**同名段，三边被覆盖得一模一样，
key 数量还是完全一致 —— 校验只会更理直气壮地报「通过」。

同族于踩坑 013：同一个概念在系统里存在两套词表。区别是 013 是两个不同的键名互相拿错，
这次是**同一个键名在同一个文件里出现两次**。

## 正确做法

**加顶层段之前先搜一次这个段名**，别靠翻文件：

```bash
grep -c '^  "transportType": {' customer-portal/src/i18n/locales/*.json
# 结果必须是 1；出现 2 就是撞了
```

已经存在就复用已有的那段（本次是把中文的「整车 (FTL)」按业务用词改成「专车 (FTL)」，
并删掉自己新加的那份），而不是另起一个同名段。

一条快速自查（三端 + 后端一起扫，输出 >1 的就是重复段）：

```bash
for f in admin customer-portal carrier-portal; do
  for l in zh en de; do
    awk -F'"' '/^  "[a-zA-Z]+": \{/ {print $2}' $f/src/i18n/locales/$l.json \
      | sort | uniq -d | sed "s|^|$f/$l 重复段: |"
  done
done
```

## 防护规则

1. **新增顶层段前必须 grep 段名**，确认当前是 0 个。加子键则要确认所在段里没有同名键。
2. **`check:i18n` 通过不代表语言包没问题**：它能查三语不一致和 key 缺失，
   查不出同文件内的重复键 —— 这类问题只有在页面上看到「文案不是我写的那个」时才暴露。
3. **文案没按预期变化时，先怀疑重复键，再怀疑缓存**。判断方法是直接问解析结果，
   不要靠肉眼翻 JSON：
   ```bash
   node -e "console.log(JSON.stringify(require('./customer-portal/src/i18n/locales/zh.json').transportType))"
   ```
   打印出来的就是页面实际会用的那份。
4. 界面改动**一定要真的打开页面看一眼**。本次三道门禁全绿，问题是靠截图发现的。

## 涉及文件

- `customer-portal/src/i18n/locales/zh.json` / `en.json` / `de.json`（删掉重复的 `transportType` 段；zh 的 FTL 文案改为「专车 (FTL)」）
- `customer-portal/src/pages/InquiryList.tsx`（用 `t('transportType.FTL')` 的那两个按钮）
- `scripts/check-i18n-keys.js`（只读确认：它按 `JSON.parse` 后比对，天然看不到重复键）
