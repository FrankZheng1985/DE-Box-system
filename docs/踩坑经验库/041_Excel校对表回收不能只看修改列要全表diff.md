# 041 · Excel 校对表回收不能只看修改列，要全表 diff

## 问题现象

德语术语校对表发给同事核对后收回，如果只顺着「修改后/Korrektur」列把填了字的
33 条直接回写语言包，会写出三处明显错误：

- 「GPS 追踪」会被改名成 `USt-IdNr.`（增值税号）
- 「我的账单」会被改名成 `IBAN`
- 「在途中」会被改成 `Kreditlimit überschritten`（信用额度超限）

## 根本原因

**人在 Excel 里填表会串行。** 核对人是对照另一张 Sheet（重点确认页）的决定往
明细页誊写的，视线来回切换时把值填进了相邻/错误的行。这类错误：

1. 单看「哪些行填了字」完全发现不了 —— 填的值本身是合法德语；
2. 只有把**填入值和所在行的原文放在一起做语义核对**才能暴露
   （"GPS Tracking → USt-IdNr." 一眼就不对）。

## 错误做法

```python
# ❌ 只遍历修改列非空的行，直接按行回写
for row in sheet:
    if row['korrektur']:
        apply(row['key'], row['korrektur'])   # 三处误填照单全收
```

## 正确做法

```python
# ✅ 1. 和发出去的原版逐格 diff，拿到"对方到底动了哪些格子"
#    （还能抓到对方改了说明列、在表尾加行这类修改列之外的动作）
# ✅ 2. 每条命中都带上该行 中文/英文/旧德语 上下文做语义核对，
#    对不上的单独列出来跟人确认，而不是静默采纳或静默丢弃
# ✅ 3. 回写按 (中文值 + 旧德语值) 精确匹配定位 key，先干跑打印全部命中再落盘
```

本次实际抓到的、只有全表 diff 才能发现的额外信息：

- 表尾**新增了一行**备注（Zu bestätigen 的语义说明）；
- **说明列被追加了文字**（Stückgut 可表达零担）—— 都不在修改列里。

## 防护规则

1. **回收校对表第一步永远是和发出去的原版做逐格 diff**，不要只扫修改列。
2. **每条修改必须过一遍"填入值 vs 所在行原文"的语义核对**；
   对不上的条目列成清单找人确认（本次 3 条全部确认为误填/错行）。
3. **回写用值匹配不用行号**：按（中文 + 旧译文)精确匹配语言包，
   行号在对方增删行后就不可信了。
4. **先干跑再落盘**，打印全部命中人工过目；落盘后 `json.load` 校验 + diff
   确认无格式噪音。
