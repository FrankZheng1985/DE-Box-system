# 066 接口原样透传数据库行，前端却按自造的字段名读

## 问题现象

订单详情页的「关联单据 / 单据流」卡片，**类型徽章和单号全是空白** ——
卡片框在、标题在、条目也按数量渲染出来了，就是每一条里面什么都没有，
点一下还会莫名其妙跳到别的页面。控制台没有任何报错。

上一天刚修完踩坑 017（单据流金额长期为 NULL），库里金额确认写进去了，
可页面上依然一个金额都看不到。

## 根本原因

**两处独立的错，叠在一起看起来像一处。**

### 错误一：前端接口是凭空写的，和后端返回对不上

后端 `getFullDocumentFlow()` 是 `SELECT * FROM flow`，把 `document_flow` 的行
原样透传给前端，字段名是表里的 snake_case：

```
preceding_doc_type / preceding_doc_id / subsequent_doc_type / subsequent_doc_id
flow_type / amount / currency / depth
```

而前端的接口声明是这样的：

```tsx
// admin/src/pages/OrderDetail.tsx —— 从上线起就是错的
interface LinkedDocument {
  id: string
  type: string
  doc_number: string
}

<span className={getDocTypeBadgeClass(doc.type)}>{t(docTypeLabelKey(doc.type))}</span>
<span>{doc.doc_number}</span>
<DocFlowItem key={doc.id} doc={doc} />
```

`doc.id`、`doc.type`、`doc.doc_number` **三个全是 `undefined`**。
后果分三层，每一层都不报错：

| 用途 | undefined 的后果 |
|------|-----------------|
| 徽章文案 `t(docTypeLabelKey(doc.type))` | 查 `docType.undefined`，i18n 静默回退成空 |
| 单号 `{doc.doc_number}` | React 对 `undefined` 的渲染就是什么都不画 |
| React key `key={doc.id}` | 全部为 `undefined`，只有 dev 模式控制台才警告 |
| 路由 `routeMap[doc.type] \|\| '#'` | 恒等于 `'#'`，`navigate('#')` 跳到一个奇怪的相对路径 |

TypeScript 一点忙都帮不上：接口是**手写的断言**，不是从后端推导出来的，
声明成什么样它就信什么样。

### 错误二：就算字段名对了，库里也拿不到要显示的东西

`document_flow` 表里只有凭证 UUID，**没有单号**。所以哪怕前端改成读
`preceding_doc_type` / `preceding_doc_id`，也只能显示一串 UUID。
「单据类型 + 单号」这个需求，靠改前端是**不可能**完成的。

同理，`preceding_doc_id` 是 `documents.id`（凭证主键），
而详情页路由 `/orders/:id`、`/quotes/:id` 吃的是**业务表主键**
（`orders.id`、`quotations.id`）。两者是两套 UUID，长得一模一样，
拿错了接口照样回 200，只是查不到记录（同族：踩坑 023）。

## 正确做法

**后端补齐展示所需的字段，前端只做展示。**

```js
// server/core/document-flow.js
// 递归 CTE 之后 LEFT JOIN documents 拿单号，再按凭证类型解析出业务主键
SELECT
  f.flow_id, f.flow_type, f.amount, f.currency, f.depth,
  f.preceding_doc_id AS doc_id,
  COALESCE(d.doc_type, f.preceding_doc_type) AS doc_type,
  d.doc_number,
  CASE d.doc_type
    WHEN 'ORD' THEN (SELECT o.id FROM orders o     WHERE o.document_id = d.id LIMIT 1)
    WHEN 'QUO' THEN (SELECT q.id FROM quotations q WHERE q.document_id = d.id LIMIT 1)
    ...
  END AS entity_id            -- ← 跳详情页只能用它，不能用凭证 id
FROM flow f
LEFT JOIN documents d ON d.id = f.preceding_doc_id   -- ← 必须 LEFT
```

`LEFT JOIN` 不能省：上游凭证被删过会在 `document_flow` 里留下悬空引用
（踩坑 061 记过这个场景），内连接会让整行凭空消失 —— 又是一个不报错的坑。

```tsx
// admin/src/pages/OrderDetail.tsx —— 字段名与后端返回逐个对齐
interface LinkedDocument {
  flow_id: string
  doc_id: string          // 凭证 id，只做标识，不拿去拼路由
  doc_type: string        // ORD / QUO / INQ / CMR / FI_AR / FI_AP …（大写码）
  doc_number: string | null
  entity_id: string | null   // 业务单据主键，跳详情页用这个
  amount: string | null      // NUMERIC → pg 驱动回字符串
  currency: string | null
}
```

## 防护规则

1. **前端接口不许凭空手写**。写之前把后端那条 SQL 的 SELECT 列表找出来逐个对，
   或者直接 curl 一次接口把返回打出来。对不上的字段 TypeScript 永远不会告诉你。
2. **接口 `SELECT *` 原样透传时，前端接口就是 snake_case**，别顺手写成 camelCase 或自己起名。
   本项目已在 CLAUDE.md 第 4 条写死了这个约定。
3. **「页面上某块是空的」优先怀疑字段名，不要先怀疑数据没存**。
   查证方法：`console.log` 整个对象看真实键名，而不是看你期待的那个键有没有值 ——
   后者永远是 `undefined`，什么也证明不了。
4. **凭证 id 和业务 id 是两套 UUID，别混用**。凡是要拼 `/xxx/:id` 路由的地方，
   问一句「这个 id 是从哪张表来的」。
5. 同族坑：**040**（空表让前端字段名写错永远暴露不出来）、
   **049**（修好了存储却没修展示）、**023**（`Number(uuid)` 静默失败）。
   共同点都是：**不报错的失败**。
