# 027 被拦下的信用检查日志会随事务回滚一起消失

> 发现日期：2026-08-02（P7 开发时）
> 涉及模块：`server/core/credit-manager.js`、`server/modules/order/service.js`

---

## 问题现象

客户信用超额，下单被系统拦下，运营看到报错「信用检查未通过」。
但到「客户 → 信用风控」里查检查日志，**一条拦截记录都没有**，
财务想事后追「谁在什么时候被拦了、拦的是哪一单、当时敞口多少」，查无实据。

## 根本原因

`createOrder` 整个跑在 `withTransaction` 里，信用检查是第一步：

```js
await withTransaction(async (client) => {
  const creditResult = await creditManager.checkCredit(client, ...)   // 日志写在 client 上
  if (creditResult.status === 'BLOCKED') {
    throw new Error(`信用检查未通过: ${creditResult.message}`)        // ← 抛错
  }
  ...
})
```

`checkCredit` 内部用**同一个事务连接** `client` 往 `credit_check_logs` 插日志。
抛错 → 事务回滚 → 刚插进去的日志跟着一起被撤销。

**越是需要留痕的结果（BLOCKED），越是必然回滚**，这是这个坑最别扭的地方：
PASSED 的日志一条不少地留下来了，真正有价值的那些全没了。

## 错误代码

```js
// credit-manager.js —— 全部走事务连接
async _logAndReturn(client, clientId, ..., result, message) {
  await client.query(`INSERT INTO credit_check_logs (...) VALUES (...)`, params)
  return { status: result, exposure, limit, message }
}
```

## 正确代码

按结果分流：PASSED 跟着事务走，WARNING / BLOCKED 用**独立池连接**写，不受回滚影响。

```js
import { query } from './db.js'   // 池连接，独立于任何事务

async _logAndReturn(client, clientId, ..., result, message) {
  const sql = `INSERT INTO credit_check_logs (...) VALUES (...) RETURNING id`

  // WARNING / BLOCKED 的日志必须写在事务之外：
  // BLOCKED 会让 createOrder 抛错 → 事务回滚 → 日志跟着没了
  const logResult = result === 'PASSED'
    ? await client.query(sql, params)
    : await query(sql, params)

  return { status: result, exposure, limit, message, logId: logResult.rows[0].id }
}
```

同一个道理适用于**通知**：信用预警通知也不能用事务连接发，否则 BLOCKED 时
财务永远收不到那条最该收到的预警。

```js
// order/service.js
async function notifyCreditAlert(clientId, creditResult) {
  const pool = getPool()          // ← 不是 createOrder 的事务 client
  await notificationEngine.notify(pool, { ... })
}
```

## 防护规则

1. **写「失败留痕」类数据前先问一句：这个事务会不会因为这次失败而回滚？**
   会回滚的话，日志/审计/告警必须走独立连接，不能搭事务的车。
2. 典型的「失败留痕」场景：信用拦截、风控拒绝、额度校验失败、
   幂等冲突记录、外部接口调用失败记录。
3. 反过来，**成功路径的日志要留在事务里**——否则主数据回滚了，
   日志却说操作成功了，比没有日志更误导人。
4. 独立连接写完之后主流程照常抛错，两件事互不干扰。
   通知发送失败要 `try/catch` 吞掉，别让「通知发不出去」把「下单被拦」
   这条真正的错误信息盖过去。

## 涉及文件

| 文件 | 说明 |
|------|------|
| `server/core/credit-manager.js` | `_logAndReturn` 按结果分流连接，并返回 `logId` |
| `server/modules/order/service.js` | `notifyCreditAlert` 用 `getPool()` 发预警 |
