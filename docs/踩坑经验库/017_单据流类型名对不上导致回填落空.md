# 017 单据流的 flow_type 不是你写的那个值，显式建连线被静默跳过

## 问题现象

写迁移 107 时要给存量报价补 `converted_order_id`，靠单据流反查"这张报价建出过哪张订单"：

```sql
UPDATE quotations q SET converted_order_id = o.id
FROM document_flow df JOIN orders o ON o.document_id = df.subsequent_doc_id
WHERE df.preceding_doc_id = q.document_id
  AND df.flow_type = 'QUOTATION_TO_ORDER';   -- ← 命中 0 行
```

SQL 语法完全正确、表和列都存在、跑起来不报任何错，**就是一行都更新不到**。

## 根本原因

`order/service.js` 里明明白白写着建 `QUOTATION_TO_ORDER` 连线：

```js
await documentFlow.createFlowLink(client, {
  precedingDocType: 'QUO', subsequentDocType: 'ORD',
  flowType: 'QUOTATION_TO_ORDER',
  amount: orderData.clientPrice, currency: orderData.currency
})
```

但库里实际存的是 **`QUO_TO_ORD`**，而且 `amount` 是 NULL。

原因是**同一条连线被建了两次，第一次赢了**：

1. 前面几行 `documentEngine.createDocument()` 传了 `sourceDocType: 'QUO'`，
   凭证引擎内部会自动建一条连线，类型名是**拼出来的**：
   ```js
   const flowType = `${sourceDocType}_TO_${docType}`   // 'QUO' + '_TO_' + 'ORD'
   ```
2. 随后 `createFlowLink` 想再建一条，撞上唯一约束：
   ```sql
   ON CONFLICT (preceding_doc_id, subsequent_doc_id) DO NOTHING
   ```
   **DO NOTHING 把它整条丢掉了** —— 不只是 flow_type 没改成 `QUOTATION_TO_ORDER`，
   连本该带上的 `amount` / `currency` 也一起没了。

所以那段显式 `createFlowLink` 从上线到现在**一次都没生效过**，
而且因为 `DO NOTHING` 不报错、不返回受影响行数，谁也没发现。

## 怎么发现的

不是靠读代码发现的 —— 读代码只会看到 `flowType: 'QUOTATION_TO_ORDER'` 然后信以为真。
是跑了一次真实的「接受报价 → 自动建单」，然后**把 document_flow 表打出来看**：

```
单据流: [{"flow_type":"QUO_TO_ORD","amount":null}]
```

## 正确做法

迁移里两个值都匹配，将来那句 `createFlowLink` 被修好也不会漏：

```sql
AND df.flow_type IN ('QUO_TO_ORD', 'QUOTATION_TO_ORDER')
```

同时新增 `quotations.converted_order_id` 外键，让"这张报价建没建单"有**唯一事实来源**，
不再依赖反查单据流、也不靠 status 推断。

## 防护规则

1. **凡是靠某个字面值去 WHERE 的迁移/查询，先去库里 `SELECT DISTINCT 那一列` 看真实取值**，
   不要照抄源码里写的常量 —— 中间可能隔着一层拼接或另一个写入方。
2. **`ON CONFLICT ... DO NOTHING` 会静默丢弃整行**。当第二次写入带着第一次没有的信息
   （本例的 amount/currency）时，DO NOTHING 就是在丢数据。这种场景要用
   `DO UPDATE SET x = COALESCE(表.x, EXCLUDED.x)` 补齐，而不是直接放弃。
3. **同一份数据有两个写入方时必须查清谁先谁后**。凭证引擎的 `createDocument`
   传了 `sourceDocType` 就会自动建单据流，业务层不必也不该再建一次。
4. 验证"写进去了吗"要**直接查表**，不能只看接口返回 200。

## 遗留

`server/modules/order/service.js` 里那段死掉的 `createFlowLink` 本次**没有动**
（它属于 order 模块的既有行为，改动影响面超出 P3 范围）。
后果是**所有** QUO→ORD 单据流的 `amount`/`currency` 都是 NULL，
单据流视图上看不到金额。修的时候建议改 `document-flow.js` 的 ON CONFLICT 为
补齐空值，而不是在业务层重复建连线。
