# 018 前端指向不存在的路由 / 不存在的返回字段（"点了没反应"类 bug）

## 问题现象

P3 开发时在 `admin/src/pages/QuotationManagement.tsx` 一页里挖出四处，
共同点是**页面不报错、控制台不报错，只是功能悄悄不工作**：

| 现象 | 用户看到的 |
|------|-----------|
| 报价列表的编号列空白、路线永远 `-`、金额永远 €0.00 | 以为是"还没数据" |
| 统计卡片"本月报价/待回复"永远 0、转化率 NaN → 0.0% | 以为是"这个月没开过报价" |
| 点「查看」「编辑」跳到白屏 | 以为是页面还没做 |
| 点「一键下单」订单建成功了，但跳转到 `/orders/undefined` | 以为是"跳转有点问题" |

## 根本原因

四处分别是四种"对不上"，但都不会抛异常：

### 1. 读了后端不返回的字段（踩坑 003 的重演）

```ts
interface Quotation {
  quote_number: string    // 后端返回的是 quotation_number
  amount: number          // 后端返回的是 total_price
  route: string           // 后端返回的是 route_from / route_to 两个 JSONB
}
```
`q.quote_number` 是 `undefined`，React 渲染 `undefined` 就是**什么都不渲染**，不报错。
`formatCurrency(undefined)` 经 `Intl.NumberFormat` 出来是 `NaN`，显示成 €0.00 或 NaN。

### 2. 统计接口混用了命名风格

后端 `GET /quotations/stats` 返回的是 `month_total` / `pending_response` /
**`conversionRate`**（一堆 snake_case 里混进一个 camelCase），
前端读 `monthly_total` / `pending_reply` / `conversion_rate` —— 三个全对不上。

### 3. navigate 到一个没注册的路由

```tsx
navigate(`/quotations/${q.id}`)   // App.tsx 里注册的是 /quotes/:id
```
React Router 匹配不到就渲染空白，**不报错也不 404**。

### 4. 读了接口没返回的那一层

```ts
const res = await api.post<ApiResponse<{ orderId: string }>>('.../convert-order', ...)
navigate(`/orders/${res.data.orderId}`)   // 后端返回的是订单对象本身，主键叫 id
```
`res.data.orderId` 是 `undefined`，模板字符串照样拼得出 `/orders/undefined`。

顺带一提：同一处还传了 `cargoDescription: quotation.route`，
而 `quotation.route` 本身就是第 1 类问题里那个不存在的字段 —— **一个错喂给另一个错**。

## 为什么 TypeScript 没拦住

因为 interface 是**手写的断言**，不是从后端生成的。
只要 interface 里声明了 `quote_number: string`，TS 就认为它存在，
`q.quote_number` 类型是 `string` 而不是 `undefined` —— 类型检查全绿，运行时全空。
`npm run build` 更拦不住（踩坑 014：Vite 只转译不查类型）。

## 正确做法

```ts
// 1. interface 字段名逐个对照后端 SQL 的 SELECT 列表，不凭印象写
interface Quotation {
  quotation_number: string
  total_price: string | null     // NUMERIC 回来是字符串（踩坑 002）
  route_from: { country?: string; city?: string } | null
  route_to: { country?: string; city?: string } | null
}

// 2. 后端接口的返回字段统一 snake_case，不要混
data: { ...r, conversion_rate: ... }   // 不要 conversionRate

// 3. navigate 的路径去 App.tsx 里搜一遍确实注册过
navigate(`/quotes/${q.id}`)

// 4. 读嵌套字段前，先看后端那个 res.json(...) 到底放了什么
const res = await api.post<ApiResponse<{ id: string }>>(...)
navigate(`/orders/${res.data.id}`)
```

## 防护规则

1. **写前端 interface 时，把后端那段 SQL 的 SELECT 列表并排放着抄**，
   一个字段一个字段对。凭印象写出来的字段名就是这类 bug 的源头。
2. **每加一个 `navigate('/xxx')` 就去 `App.tsx` 搜一次 `/xxx`**，搜不到就是错的。
   跳转到未注册路由是白屏，没有任何报错提示。
3. **前端渲染出 `-` / 空白 / 0 / NaN 时，先怀疑字段名，再怀疑没数据。**
   `q.foo || '-'` 这类兜底会把"字段名写错了"伪装成"这条没填"（踩坑 013 防护规则 2 同理）。
4. **接口一端改了返回结构，另一端必须同步**：形状、取值、类型、嵌套层级四项都要看（踩坑 011）。
5. 联调时至少走通一次完整链路并**看真实落库/真实跳转结果**，别只看 toast 说"成功"（踩坑 016）。
