# 059 · 空日期以空串进 SQL，会让整条保存失败，连带其他字段一起丢

## 问题现象

管理端「运输公司 → 编辑 → 保存修改」，只要许可证有效期 / 保险有效期是空的，保存就报：

```
invalid input syntax for type date: ""
```

要命的不是日期没存上，而是**整条 UPDATE 一起回滚**——同一次提交里刚勾的车辆类型、
刚改的服务国家全都没进库。用户看到的是"我明明勾了车型，保存完还是空的"，
根本不会联想到是日期字段的锅。

## 根本原因

两层原因叠在一起，缺一不可：

### 1. `<input type="date">` 留空提交的是空字符串，不是 null

前端 `CarrierEdit.tsx` 提交时 `...form` 原样带过去，空日期就是 `''`：

```ts
const payload = { ...form, ... }   // form.licenseExpiry === ''
```

后端 `carrier/routes.js` 的 PUT 用 `!== undefined` 判断要不要写这个列，
`''` 不是 `undefined`，于是被推进 SQL：

```js
if (req.body[camel] !== undefined) {
  params.push(req.body[camel])          // 推进去的是 ''
  setClauses.push(`${snake} = $${++idx}`)
}
```

Postgres 的 `date` 列拒收 `''`（不像 `text` 列会照单全收），整条语句报错。
因为在 `withTransaction` 里，事务回滚，**同一次提交的所有字段一起没了**。

### 2. 日期回填是坏的，导致"有值也显示成空"（踩坑 039 的同款）

`carriers.license_expiry` 是 `date` 列，经 pg 驱动 → JSON 序列化后是
`"2028-12-30T16:00:00.000Z"`（库里其实是 2028-12-31）。这串直接塞给
`<input type="date">` 是**非法值，浏览器会静默显示成空白**：

```js
const i = document.createElement('input'); i.type = 'date'
i.value = "2028-12-30T16:00:00.000Z"
i.value   // → ""   ← 就这么没了
```

所以打开编辑页时，两个日期框看起来"本来就没填"。用户什么都不改点保存，
提交的就是 `''` → 触发上面那个报错。

**两个坑必须一起修**：只修后端（`'' → null`）的话，报错是没了，
但保存会**把库里原有的日期悄悄清成 null**——从"显式报错"变成"静默丢数据"，更糟。

## 错误代码

```js
// ❌ 后端：'' 会被当成"用户填了值"推进 SQL
if (req.body[camel] !== undefined) { params.push(req.body[camel]) }
```

```ts
// ❌ 前端：ISO 串直接塞 date 框，框子变空白
licenseExpiry: d.license_expiry || d.licenseExpiry || '',
```

## 正确代码

```js
// ✅ 后端统一兜住：空日期转 null，前端各页面就不用各自记得转
const DATE_FIELDS = ['licenseExpiry', 'insuranceExpiry']

function normalizeDateFields(body) {
  for (const field of DATE_FIELDS) {
    if (typeof body[field] === 'string' && body[field].trim() === '') {
      body[field] = null
    }
  }
}
// POST / PUT 入口第一行调用
```

```ts
// ✅ 前端回填走 toDateInputValue（踩坑 039 就为这个加的）
licenseExpiry: toDateInputValue(d.license_expiry || d.licenseExpiry),
```

## 防护规则

1. **凡是往 `date` / `timestamp` 列写值的接口，空串必须在后端转成 null**。
   在后端统一兜住，不要指望每个前端页面都记得转——本项目三端（运营/客户/承运商）
   加上导入脚本都可能往同一张表写。
2. **`!== undefined` 这种"传了就写"的判断，对日期列是危险的**。
   字符串列 `''` 无害，日期/数字列 `''` 直接报错。写这类动态 SET 语句时，
   先列清楚哪些是非文本列。
3. **凡是 `<input type="date">` 的回填，一律走 `toDateInputValue()`**（同踩坑 039）。
   非法值不会报错、不会白屏，只会显示成空白，然后被用户"顺手"保存掉。
4. **改完必须查库验证，不能只看"保存成功"提示**。本次就是要确认
   `license_expiry` 真的是 `null`、`vehicle_types` 真的多了刚勾的项。
5. 排查线索：**"我改的 A 没存上"但 A 的代码看着完全正确时，
   先看同一次提交里有没有别的字段把整条事务搞挂了**，别死盯着 A。
