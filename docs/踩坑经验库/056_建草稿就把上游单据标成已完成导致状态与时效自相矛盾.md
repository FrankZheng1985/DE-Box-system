# 056 建草稿就把上游单据标成「已完成」，状态与时效自相矛盾

## 问题现象

客户门户询价页：一张询价单状态显示**「已报价」**，同一行的**「报价时效」列却是横杠**。
客户点进「我的报价」页又一张报价都看不到——三处说法互相打架。

运营侧同样被误导：询价列表显示已报价，实际草稿还躺在系统里没发出去，
这单在「待报价」的待办里也不会再出现，容易漏发。

## 根本原因

`POST /api/v1/quotations` 新建的报价**固定是 `DRAFT`**（发送是另一个动作），
但建完顺手把来源询价改成了 `QUOTED`：

```js
// server/modules/quotation/routes.js（旧）
[..., 'DRAFT', req.body.remarks, req.user.id, ...]   // 报价是草稿

if (req.body.inquiryId) {
  await client.query(`UPDATE inquiries SET status = 'QUOTED' WHERE id = $1`, [req.body.inquiryId])
}
```

而报价时效统计（`server/modules/inquiry/routes.js`）刻意只认**非草稿**报价：

```sql
SELECT MIN(q.created_at) FROM quotations q
 WHERE q.inquiry_id = i.id AND q.status <> 'DRAFT'
```

两处对「算不算已经报价了」的口径不一致，于是状态说已报价、时效说还没报价。

**更一般的教训**：下游单据刚建出来还是草稿时，上游单据的状态不能跟着往前走。
状态字段该跟的是「客户/对方实际收到了什么」，不是「我方系统里建了什么」。
踩坑 054 把草稿从客户的接口里挡掉之后，这个矛盾更明显了：
客户什么都看不到，询价却写着已报价。

## 正确做法

把上游状态的推进挂到**真正发出去的那个动作**上，并且只从等待态推进：

```js
// POST /quotations —— 建草稿，不动询价状态

// POST /quotations/:id/send —— 这里才推进
const updated = await client.query(
  `UPDATE quotations SET status = $1 WHERE id = $2 AND status = $3 RETURNING id, inquiry_id`,
  [QUOTATION_STATUS.SENT, req.params.id, QUOTATION_STATUS.DRAFT]
)
const inquiryId = updated.rows[0].inquiry_id
if (inquiryId) {
  await client.query(
    `UPDATE inquiries SET status = 'QUOTED', updated_at = NOW()
      WHERE id = $1 AND status = 'PENDING_QUOTE'`,   // ← 条件不能省
    [inquiryId]
  )
}
```

`AND status = 'PENDING_QUOTE'` 不是可有可无的保险：补发历史报价、发送新版本报价
都会走到 `/send`，没有这个条件就会把已 `ACCEPTED` / `REJECTED` / `CANCELLED`
的询价倒回「已报价」，抹掉客户已经做过的决策。

## 存量数据

代码改了只管新单，旧的脏状态要单独修：

```bash
node server/scripts/fix-inquiry-quoted-without-sent.js         # 只查
node server/scripts/fix-inquiry-quoted-without-sent.js --fix   # 退回 PENDING_QUOTE
```

只回退 `QUOTED` 的单；`ACCEPTED` / `REJECTED` 是客户已决策的事实，不能动。

## 防护规则

1. **建草稿不推进上游状态**，状态推进永远挂在"对方真正收到"的那个动作上。
2. **同一件事有两个地方判断（状态字段 + 统计口径），必须共用同一个判据**；
   不能一处按"有没有记录"、另一处按"记录是不是草稿"。
3. **改状态的 UPDATE 一律带上「从哪个状态来」的条件**，别裸 `WHERE id = $1`。
4. 类似的状态推进点还有：订单、CMR、清关——新增时先问一句
   "这个动作之后，对方看得到东西了吗？"

| `server/modules/quotation/routes.js` | 建报价不再改询价状态；发送成功后才置 QUOTED |
