# 055 后端渲染的"成品"跟着界面语言走，等于给错了收件人

**日期**：2026-08-07
**模块**：询价（inquiry）— 复制摘要 / 导出 Excel

---

## 问题现象

询价页的「复制摘要」按钮，生成的文本从头到尾是中文：

```
询价单号：INQ-20260806-0002
【起运地】
国家：DE
【货物明细】
1. 单号 1 | TABLE | 1 件 | 200×150×150 cm
```

而这段文本的**唯一用途**就是粘给欧洲服务商询价，对方一个字看不懂。
旁边的「导出 Excel」同理，表头和「服务类型／状态」两列的值也是中文。

功能本身没报错，测试也测不出来——它"正确地"输出了中文。

## 根本原因

P9 上三语时，后端 `resolveLang(req)` 的实现是：

```
Accept-Language 头 → 登录用户的 users.language → 默认中文
```

前端 `api.ts` 会把**当前界面语言**塞进 Accept-Language。这个链路对
"给操作员看的东西"（导入模板、导入报错）完全正确，但对
"后端渲染完直接转给第三方的东西"就是错的：

> **它翻译成了"操作员在看什么语言"，而不是"这份东西要给谁看"。**

清平姐界面开中文 → 摘要就是中文 → 粘给西班牙服务商。
翻译链路每一环都在正常工作，结果照样送错人。

## 判断方法

给后端要渲染的每一段文案问一句：**这份产物最终落在谁眼前？**

| 产物 | 收件人 | 该用什么语言 |
|------|--------|------------|
| 复制摘要、导出给服务商的 Excel | 欧洲服务商 | **固定英文**（默认），中文只是可选 |
| 导入模板、导入报错 | 操作员／客户自己 | 跟界面语言（`resolveLang`） |
| API 响应 message | 前端 | 走 messageCode，前端自己翻 |

收件人不是当前请求的发起人时，`resolveLang(req)` 就不能用。

## 解决方案

在 `server/modules/inquiry/routes.js` 里单独开一个解析函数，和 `resolveLang` 分家：

```js
// ✅ 转给服务商的成品：只认显式 ?lang=，默认英文
function resolveCarrierDocLang(req) {
  return normalizeLang(req.query?.lang) || 'en'
}
```

摘要两个端点 ＋ 导出 Excel 用它；导入模板和导入报错**继续用 `resolveLang`**。

## 连带的第二个坑：表头翻了，值没翻

Excel 改完第一版时，表头已经是英文，但单元格里还是中文——
因为「服务类型／状态」两列的值走的是模块顶部两张写死的中文常量表：

```js
// ❌ 表头走 t(lang) 翻译了，值却还从这里取
const BUSINESS_TYPE_LABELS = { TRUCK_LTL: '卡车派送 LTL', ... }
const STATUS_LABELS = { ACCEPTED: '已接受', ... }
```

产出一份**表头英文、内容中文**的半成品，比全中文更难看。

```js
// ✅ 值也过语言包；查不到就退回原始代码，别露出 "inquiryStatus.XXX"
function enumLabel(section, code, lang) {
  if (!code) return ''
  const label = t(lang, `${section}.${code}`)
  return label.startsWith(`${section}.`) ? code : label
}
```

## 防护规则

1. **后端自渲染文案改语言时，表头和值要一起查**。搜 `t(lang,` 只能找到已经接入
   语言包的地方，那些写死的 `XXX_LABELS` 常量表**搜不到**，得单独 grep 一遍
   `_LABELS`、`= {` 这类中文字面量常量。
2. **默认值要按收件人定，不是按"哪个更通用"定**。这次默认英文是因为收件人是
   欧洲服务商；换成给国内客户的对账单，默认就该是中文。
3. **验证必须真下载产物看**，不能只看接口 200。本次是把 xlsx 下回来用 ExcelJS
   读表头和单元格才发现值没翻——接口从头到尾都是 200。
4. **请求头要故意设成反的**：验"不跟界面语言走"，就得带 `Accept-Language: zh-CN`
   去请求，看回来的是不是英文。用默认头测等于没测。
5. 摘要/Excel 的键用的是模板字符串 `t(lang, \`inquirySummary.${key}\`)`，
   `check-i18n-keys.js` 的静态扫描**认不出来**。以后加字段，三语包必须手工补齐，
   别指望校验脚本报错。
