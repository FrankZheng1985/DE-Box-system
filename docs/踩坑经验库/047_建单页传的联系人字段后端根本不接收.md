# 047 建单页传的联系人字段后端根本不接收

## 问题现象

运营端建单页（`admin/src/pages/OrderCreate.tsx`）上有四个联系人字段：
装货联系人 / 装货电话 / 卸货联系人 / 卸货电话，页面能填、能提交、提交后
**订单创建成功、没有任何报错**。

但订单详情里从来看不到这些联系人 —— 而且不是"显示没做"，是**数据压根没进库**。
做客户门户建单改造时顺手全局搜了一遍才发现：

```bash
grep -rn "pickup_contact\|pickupContact\|delivery_contact\|deliveryContact" server/
# 一条都搜不到
```

前端传了整整四个字段，后端从上到下**没有任何一处提到过它们**。

## 根本原因

`orders` 表只有 `pickup_address` / `delivery_address` 两个 JSONB 列，**没有联系人列**。
`server/modules/order/model.js` 的 `create()` 是把参数一个一个点名取出来拼 SQL 的：

```js
data.pickupAddress, data.deliveryAddress, data.pickupDate, ...
```

没被点到名的 `data.pickupContact` 就是个多余的对象属性，**JS 不会报错，SQL 也不会报错**，
它跟着请求体进来，又跟着垃圾回收走了。

这是"前后端契约对不上"的又一种形态（踩坑 011 / 033 同族）：
不是字段名写错、不是类型不对，而是**这个字段在后端根本不存在**，
而 REST + 动态对象的组合决定了这种错永远是静默的。

## 正确代码

不新增数据库列（改表结构要走影响面评估），把联系人**并进已有的地址 JSONB**，
在 service 层统一处理，三个入口（运营建单 / 门户建单 / 批量导入）一次性都修好：

```js
// server/modules/order/service.js
function mergeContactIntoAddress(address, contactName, contactPhone) {
  const name = (contactName || '').trim()
  const phone = (contactPhone || '').trim()
  if (!name && !phone) return address   // 都没填就保持原样，别造出空对象
  return {
    ...(address || {}),
    ...(name ? { contactName: name } : {}),
    ...(phone ? { contactPhone: phone } : {})
  }
}

const order = await orderModel.create(client, {
  ...orderData,
  pickupAddress: mergeContactIntoAddress(
    orderData.pickupAddress, orderData.pickupContact, orderData.pickupPhone
  ),
  deliveryAddress: mergeContactIntoAddress(
    orderData.deliveryAddress, orderData.deliveryContact, orderData.deliveryPhone
  ),
  ...
})
```

## 防护规则

1. **新增表单字段时，最后一步是全局搜一次这个字段名**，要能在后端搜到落点
   （model 的 INSERT 列 / service 的显式处理）。搜不到就是没接。
2. **判断"字段有没有存进去"以查库为准**，不要以"接口回了 200 / 页面没报错"为准。
   本项目建单接口即使收到一堆不认识的字段也照样回 200。
3. 新写字段落 JSONB 时，**空值要返回 `null` 而不是 `{}`**，
   否则查询里 `address->>'city'` 全变成空字符串，比 NULL 更难排查。
4. 自测脚本里对新字段加一条**查库断言**（本次批量导入的自测就断言了
   `pickup_address.contactName === 'Max'`），比人工点页面靠谱。

- `server/modules/order/model.js`（只读确认，未改）
