# 踩坑记录 003：前后端字段名不一致导致数据不显示

## 问题现象
订单列表页面加载成功（200），但表格中客户名、路线、重量、报价等字段全部显示为空或 `-`。

## 根本原因
后端 API 返回 **snake_case** 字段名，前端 TypeScript interface 用的是 **camelCase**。

```javascript
// 后端返回
{ order_number: "EU-2026...", client_name: "BMW AG", pickup_city: "Munich" }

// 前端期望
{ orderNo: "EU-2026...", customerName: "BMW AG", originCity: "Munich" }

// 结果：order.customerName === undefined
```

## 解决方案
**方案一（推荐）：前端 interface 直接用 snake_case**
```typescript
interface Order {
  order_number: string    // 不用 orderNo
  client_name: string     // 不用 customerName
  pickup_city: string     // 不用 originCity
}
```

**方案二：获取数据时做映射**
```typescript
const mapped = data.map(o => ({
  orderNo: o.order_number,
  customerName: o.client_name,
}))
```

## 受影响的页面
- OrderManagement.tsx — 订单列表（所有字段）
- 承运商门户 Dashboard — stats 字段
- FinanceManagement.tsx — 利润分析 tab（2026-08-01 修复，见下方补充案例）

## 补充案例（2026-08-01）：snake_case 也救不了"猜出来的字段名"

财务页利润分析卡片读 `p.client_name` / `p.revenue` / `p.margin`，
但后端 `/finance/profit/by-client` 的 SQL 实际 SELECT 的是
`company_name`、`total_revenue`、`margin_pct`——前端 interface 明明用了 snake_case，
字段名却是**想当然编的**，没有一个和 SQL 别名对得上。
结果：卡片标题空白、所有卡片 React key 都是 `undefined`（重复 key 警告），
金额靠 JSX 里 `p.total_revenue || p.revenue` 的兜底才碰巧显示（TS 报 TS2339 被无视）。

教训：**光统一 snake_case 不够，interface 的每个字段名必须打开后端 SQL/路由照抄，
不能凭记忆写**；tsc 报 TS2339（属性不存在）时就是契约错位的信号，不要用 `|| 兜底` 糊过去。

## 防护规则
**新建前端 interface 时，字段名必须与后端 API 返回的 JSON key 完全一致（snake_case），不要自己起 camelCase 名字；也不要凭记忆猜 snake_case 名字，必须打开后端代码照抄 SELECT 别名。**
