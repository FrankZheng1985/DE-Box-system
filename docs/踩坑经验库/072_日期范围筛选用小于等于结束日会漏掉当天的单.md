# 072 · 日期范围筛选用 `<= 结束日`，当天的单一条都筛不出来

> 发现日期：2026-09-05（给客户门户询价列表加日期筛选时，做对照实测撞出来的）
> 涉及文件：`server/modules/inquiry/routes.js`（已修）、`server/modules/order/model.js`（**同样的写法，尚未修**）

## 问题现象

列表按建单日期筛选，"从今天到今天"筛出来是**空的** —— 而今天明明建了 10 张单。
往前选一天（昨天→今天）又能筛出昨天的，唯独当天的永远漏掉。

不报错、不空指针，就是"这一天没有数据"的样子，非常像业务上真的没单。

## 根本原因

`created_at` 是 `timestamp`（带时分秒），而筛选传进来的是纯日期字符串：

```sql
AND i.created_at <= '2026-09-05'
```

PostgreSQL 会把 `'2026-09-05'` 当成 **`2026-09-05 00:00:00`**。
于是当天 00:00:00 之后建的单（也就是当天所有的单）全部 `> 结束日`，被条件排除。

**日期越靠近今天，漏得越彻底**：昨天的单能筛出来，今天的一条都出不来。

## 错误代码

```js
if (dateTo) { params.push(dateTo); sql += ` AND i.created_at <= $${++idx}` }
```

## 正确代码

结束日要按「小于次日零点」算，才等于"包含这一整天"：

```js
if (dateFrom) { params.push(dateFrom); sql += ` AND i.created_at >= $${++idx}::date` }
if (dateTo)   { params.push(dateTo);   sql += ` AND i.created_at < ($${++idx}::date + 1)` }
```

## 怎么验才算数

**只跑新写法看到"有数据"不算验证过** —— 得让新旧两种写法跑出**不同的结果**：

```sql
-- 旧写法：命中 0
SELECT COUNT(*) FROM inquiries
WHERE created_at >= '2026-09-05'::date AND created_at <= '2026-09-05'::date;

-- 新写法：命中 10
SELECT COUNT(*) FROM inquiries
WHERE created_at >= '2026-09-05'::date AND created_at < ('2026-09-05'::date + 1);
```

两条数字不一样，才说明改动真的生效、也真的修掉了问题。

## 防护规则

1. **凡是拿纯日期去比 timestamp 列，结束边界一律写 `< 次日`，不要写 `<= 当日`**。
   起始边界用 `>= 当日` 是对的，不用改。
2. 加日期筛选后**必须拿"今天到今天"实测一次**：这是最容易漏、也最常被用户点的组合
   （运营和客户想看"今天进了多少单"，点的就是它）。
3. 对照着验：新旧两种写法的命中数必须不同。只跑一边永远发现不了它根本没生效。

## 同族点（2026-09-05 已一并修完）

`server/modules/order/model.js` 的订单列表和 `server/modules/order/routes.js` 的
`/orders/export` 导出，原先用的都是旧写法：

```js
if (dateTo) { params.push(dateTo); sql += ` AND o.created_at <= $${++paramIdx}` }
```

**管理端订单页按日期筛「到今天」会漏掉今天的所有订单**，导出同理。

⚠️ 这两处各有一份**独立的 SQL**（列表在 model.js、导出在 routes.js 里另写了一遍），
不是共用同一段代码，所以必须一起改 —— 只改一处会变成「页面看得到、导出里没有」，
比全都漏掉更难发现。

已按上面的正确写法修掉。对照实测：造一条今天创建的订单，按「今天 → 今天」筛，
新写法命中 1 条、旧写法命中 0 条，两者不同才算修复真的生效。
