# 075 · 缺失值「按 0 兜底」，一旦放开部分填写，就会把「还没报」变成「报了 0 元」

> 发现日期：2026-09-28（做开发意见 #23「本地派送允许部分报价」时）
> 涉及文件：`server/modules/quotation/service.js`（`replaceDeliveryLines`、`loadDeliveryOrdersForConversion`、`createOrderFromQuotation`）

## 问题现象

本地派送报价「一柜多票、按票报价」。原来有两处兜底：

1. 保存逐票报价时，**空价按 0 写入**（注释理由：跳过会让这一票在报价单上凭空消失）；
2. 客户接受报价、按票建单时，**没有报价行的票按 0 元建单**（`COALESCE(l.price, 0)`，理由：宁可建 0 元单让人看见，也别让货没人管）。

在「前端强制每票必填」的前提下，这两处永远走不到，所以一直相安无事。
苏总提出「服务商回价有早有晚，要能先报一部分」——前端一放开必填，两处兜底立刻变成事故：
**运营只报了 1 票，客户点接受，系统就给另外 2 票各建一张 0 元订单**。

反向对照实测过：去掉本次加的拦截，部分报价被接受，建出了 `€50 / €0 / €0` 三张订单。

## 根本原因

「缺失」和「0」被当成了同一个东西。
按 0 兜底只有在「上游保证不会缺失」时才无害；它把一个本该显式处理的状态（还没报）悄悄折叠进了一个合法的业务值（免费送），
而这个假设写在**前端校验**里，后端自己并不知道。上游约束一放宽，下游兜底就成了静默的错账。

这和全局规范里「判『有没有值』不要写 `> 0`」是同一个病根：**把「缺失」和「某个具体值」混为一谈**。

## 解决方案

- 用「**有没有报价行**」表示「报没报」，空价**不写行**（`isBlankPrice` 跳过），0 照常写行 = 免费送。无需改表结构。
- 转单前查出 `line_id`，只要有一票为空就抛错，拦在 `createOrderFromQuotation` ——门户、邮件链接、运营手工转单三条路都经过这里。
- 一票都没填时直接报错：否则逐票行被清空，`recalcQuotationTotalFromLines` 对零行不动总价，会留下一个过期的合计。

## 防护规则

1. 写「缺失值兜底」之前先问：**这个缺失今后会不会成为一个合法状态？** 会的话，缺失必须有自己的表示（没有行 / NULL），不能折成 0。
2. 兜底的前提如果写在前端校验里，**后端注释要写明「依赖前端必填」**；放宽前端校验时，全仓 grep 这类注释 / `COALESCE(..., 0)` / `|| 0`。
3. 涉及钱的拦截做完要**反向对照**：把拦截去掉，确认用例真的会变红（本次去掉后确实建出了 0 元单）。
