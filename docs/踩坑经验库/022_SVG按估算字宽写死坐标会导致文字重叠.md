# 022 SVG 按估算字宽写死 x 坐标，文字会挤成一团

## 问题现象

手写品牌 Logo 的 SVG，把双色品牌名拆成两个 `<text>`，各自给绝对 x 坐标：

```svg
<text x="157" y="100" font-size="34" font-weight="800" letter-spacing="2.5" fill="#1C1C1E">KALUNA</text>
<text x="313" y="100" font-size="34" font-weight="800" letter-spacing="2.5" fill="#E5432E">SPED</text>
```

代码看着没问题，实际渲染出来两个词**紧贴在一起**，变成 `KALUNASPED`，
中间一点缝都没有。10 个规格的 Logo 文件全中招。

## 根本原因

`x="313"` 是我按「6 个字母 × 字号 × 权重 + letter-spacing」**估算**出来的，
估宽了实际字宽，所以 SPED 的起点落进了 KALUNA 的尾部。

更麻烦的是这个数字**不可能算准**：
- 字体不同宽度不同。`font-family="Inter, Arial, sans-serif"` 是回退链，
  装了 Inter 的机器和只有 Arial 的机器，同一串字宽度就不一样
- 字重 800 的字宽在不同字体里差异更大
- 浏览器、Illustrator、macOS 预览、PDF 渲染器各有各的字距处理

也就是说，**只要用绝对坐标拼接文字，在某些机器上必然错位**，
在自己机器上看着对，不代表客户打开是对的。

## 解决方案

用 `<tspan>` 让文字**流式排布**，靠 `dx` 给相对间距，不碰绝对坐标：

```svg
<text x="157" y="100" font-family="Inter, Arial, sans-serif"
      font-size="34" font-weight="800" letter-spacing="2.5">
  <tspan fill="#1C1C1E">KALUNA</tspan><tspan dx="10" fill="#E5432E">SPED</tspan>
</text>
```

`dx="10"` 的含义是「在上一段文字结束的位置再往右 10」，
无论 KALUNA 实际渲染多宽，间距恒定为 10，永远不会重叠。

双色、多色品牌名都该这么写。同理，`<tspan dy>` 处理多行。

## 防护规则

- **SVG 里同一行的多段文字，一律用 `tspan` + `dx`，禁止给第二段写绝对 x。**
- **手写的 SVG 必须实际渲染出来看，不能只审代码。** 字宽问题在代码层完全看不出来。
  无头渲染一张图最快：

  ```bash
  "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
    --headless --disable-gpu --screenshot=out.png \
    --window-size=1100,1100 --hide-scrollbars "file:///路径/preview.html"
  ```

- Logo 类资产验证要覆盖**真实使用场景**，不是只看单张图：
  明底 / 暗底、导航栏里的实际高度、**灰度**（CMR、报关单常是黑白打印）、
  **16px favicon**（小尺寸下细节会糊成一团）。
