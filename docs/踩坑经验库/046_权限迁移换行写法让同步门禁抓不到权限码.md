# 046 权限迁移换行写法让同步门禁抓不到权限码

## 问题现象

新增 `order:import` / `portal:order_import` 两个权限码，迁移 `123_order_import_permissions.sql`
已经写好并在本地库执行成功（`INSERT 0 1` ×2，权限表里查得到），
但跑权限同步门禁时照样报错：

```
权限码字典：98 个（来自 …… + 123_order_import_permissions.sql）
❌ 代码引用了 2 个字典里没有的权限码（必须修）：
   order:import          ← server/modules/order/routes.js
   portal:order_import   ← customer-portal/src/pages/MyOrders.tsx
```

最迷惑的地方：**报错里明明列出了 123 这个文件**，说明脚本读到了它，
所以第一反应是去查"是不是迁移没跑""是不是权限表没数据"——查了都是好的，全白查。

## 根本原因

`server/scripts/check-permission-menu-sync.js` 是**静态扫 SQL 文本**建字典的，
不连数据库。它的正则要求权限码必须出现在**行首的一个左括号后面**：

```js
for (const m of sql.matchAll(/^\s*\('([a-z_]+:[a-z_]+)'/gm)) { ... }
```

而我为了让长 INSERT 好读，把值写成了每字段一行：

```sql
-- ❌ 脚本抓不到：'order:import' 这一行前面没有左括号
INSERT INTO permissions (perm_code, perm_name, ...)
VALUES (
  'order:import',
  '批量导入订单',
  ...
)
ON CONFLICT (perm_code) DO NOTHING;
```

于是"库里有、代码里用、字典里没有"，门禁把它当成引用了不存在的权限码。

## 正确代码

每个权限码都写成「行首左括号紧跟码」：

```sql
-- ✅ 行首是 ('order:import'，正则命中
INSERT INTO permissions (perm_code, perm_name, module, module_name, perm_type, scope, sort_order, description)
VALUES
  ('order:import', '批量导入订单', 'order', '订单管理', 'ACTION', 'OPERATOR', 109,
   '按运输产品下载 Excel 模板并批量建单，导入的订单同样进入待审核'),
  ('portal:order_import', '批量下单', 'portal', '客户门户', 'ACTION', 'CLIENT', 2009,
   '客户门户：下载模板后一次性提交多张订单，同样进入待审核')
ON CONFLICT (perm_code) DO NOTHING;
```

后面的字段可以继续换行，只要**码本身在行首括号后**就行。

## 防护规则

1. **权限迁移的 INSERT 一律照 109 的排版写**：`VALUES` 换行，然后每条一行 `('码', ...)`。
   别为了排版好看把码单独放一行。
2. 新增权限码后**必须跑一次门禁**，别只看 psql 的 `INSERT 0 1`：
   ```bash
   cd server && node scripts/check-permission-menu-sync.js
   ```
   退出码 0 才算过。库里写进去了 ≠ 门禁认得。
3. 同族提醒：这个脚本对 `MENU_PERMISSIONS`、Sidebar、`routeTitleMap` 也都是**正则扫文本**，
   所以这些地方的写法只要偏离既有排版，都可能出现"代码是对的、门禁却报错"或者
   更危险的"门禁没报错但其实没配上"。改这几处时保持和邻居一样的写法。
