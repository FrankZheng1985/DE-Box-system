# 025 滚动监听不做初始同步，导航栏会停在错误状态

## 问题现象

官网滚动到白色内容区（如 Kontakt）时，导航栏的链接文字、Logo 的
「KALUNA」和图标竖条**全部消失**，整条导航只剩一个孤零零的红色 `<` 和 `SPED`。
首屏看着完全正常，一刷新就出问题。

## 根本原因

导航栏靠 `.scrolled` 类切换深浅配色，但类只在 scroll 事件里更新：

```javascript
window.addEventListener('scroll', function() {
  if (window.scrollY > 50) {
    navbar.classList.add('scrolled');
  } else {
    navbar.classList.remove('scrolled');
  }
});
// ← 页面加载时从不检查一次当前滚动位置
```

**这三种情况都不会触发 scroll 事件**，导航栏就永远停在"未滚动"态：

1. **刷新页面** —— 浏览器自动恢复上次的滚动位置（最常见，用户一刷新就中招）
2. **URL 带锚点** —— 如 `/#contact` 直接定位
3. **从其他页面返回** —— bfcache 恢复滚动位置

而 `.navbar` 的背景**本身就是白色半透明**：

```css
.navbar          { background: rgba(255,255,255,0.75); }  /* 所谓"透明"态 */
.navbar.scrolled { background: rgba(255,255,255,0.92); }
```

它在 Hero 区之所以看起来是深色，只是下面的深色大图透上来。所以一旦停在
"未滚动"态又滚到了白色内容区，`.navbar:not(.scrolled)` 的白色文字规则
就把链接和 Logo 全部刷成白色，落在白色背景上 = 隐形。

这是**既有缺陷**，只是旧 Logo 的 `BOX` 是固定橙色、图标是橙色描边，
任何时候都可见，所以一直没被发现。换成新 Logo 后竖条跟着变白，
图标缺了一半变成 `<`，问题才暴露出来。

## 解决方案

### 1. 抽成函数，加载时立即同步一次

```javascript
function syncNavbar() {
  if (window.scrollY > 50) {
    navbar.classList.add('scrolled');
  } else {
    navbar.classList.remove('scrolled');
  }
}
window.addEventListener('scroll', syncNavbar);
syncNavbar();                                 // 脚本执行时立刻同步
window.addEventListener('load', syncNavbar);  // 图片撑开布局后再同步一次
```

`load` 那次不能省：图片加载完会改变页面高度，浏览器恢复滚动位置的时机
可能在 DOMContentLoaded 之后。

### 2. 不该变色的元素就别跟着变

Logo 现在固定石墨黑 `#1C1C1E`，不再随 `.scrolled` 切换。理由是
navbar 背景**任何状态下都是白色半透明**，深色本来就两种状态都清晰；
让它跟着变白，只会在判断失效时整块消失。

> **判断原则**：一个元素要不要跟着状态变色，看它在**两种状态下**是否
> 都需要变才能看清。如果有一种颜色在两种背景下都够，就固定死——
> 少一个依赖就少一个失效点。

## 防护规则

- **凡是"根据滚动位置切换样式"的逻辑，注册监听后必须立即执行一次**，
  再补一个 `load` 事件。只写 `addEventListener('scroll')` 就是 bug。
  同理适用于 resize（响应式断点）、hashchange。
- **别用"透明"来形容白色半透明的导航栏**。真透明才能靠下层内容提供对比度；
  白色半透明意味着白字在浅色内容区必然不可见。
- **改导航栏配色后，必须测这几个场景**，只看首屏会漏：
  1. 首屏未滚动
  2. 滚动到白色内容区
  3. **刷新页面**（这个最容易漏，也最容易被用户撞上）
  4. 带锚点直接打开

## 排查时踩的弯路（值得记）

用无头浏览器验证时被自己的探测方法误导了两次：

1. **`window.scrollTo(0, 2000)` 后读 `scrollY` 仍是 0** —— 以为 window 不滚动。
   实际是 `html { scroll-behavior: smooth }` 让滚动变成**异步动画**。
   同步验证要用 `window.scrollTo({top: 2000, behavior: 'instant'})`。
2. **`getComputedStyle` 读出的颜色是白色** —— 以为有别的规则在覆盖。
   实际是元素有 `transition: color 0.3s`，刚切换 class 时读到的是
   **过渡动画的中间帧**，不是最终值。要么等过渡结束再读，要么先去掉 transition。

> 教训：无头环境里拿到反直觉的结果时，先怀疑自己的探测方法，
> 别急着断定是被测代码的 bug。
