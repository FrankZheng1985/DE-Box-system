# 070 worktree 里软链包级 node_modules 不够——workspace 把依赖提到了根

> 日期：2026-08-28
> 模块：本地验证环境（worktree + vite）
> 性质：验证环节被卡住，代码本身没问题

---

## 问题现象

在 worktree 里做界面实跑，按惯例把主工作区的依赖软链过来：

```bash
ln -s /主工作区/customer-portal/node_modules  worktree/customer-portal/node_modules
ln -s /主工作区/admin/node_modules            worktree/admin/node_modules
ln -s /主工作区/server/node_modules           worktree/server/node_modules
```

后端起得来、`tsc --noEmit` 也跑得通，一切看起来正常。
但起前端 dev server 直接 `exit 127`：

```
./node_modules/.bin/vite: No such file or directory
```

去主工作区看，`customer-portal/node_modules/` **目录确实存在**，
里面却连 `.bin/` 都没有。

## 根本原因

本仓库是 **npm workspace**（根 `package.json` 管四个包），
依赖被**提升到仓库根的 `node_modules`**，可执行文件也只在根的 `.bin/` 里：

```
德国Box系统/node_modules/.bin/vite     ← 真正的可执行文件在这
德国Box系统/customer-portal/node_modules/   ← 只剩少数无法提升的包，没有 .bin
```

所以「软链每个包自己的 node_modules」这个在非 workspace 项目里够用的做法，
在这里**只够让 tsc 这类通过 npx 回退到根的命令碰巧跑通**，
一旦直接调 `./node_modules/.bin/xxx` 就断。

危险之处是它**部分成功**：后端能起、类型检查全绿，
很容易以为环境已经就绪，然后把 127 当成 vite 装坏了去重装依赖。

## 解决方案

worktree 里**先软链仓库根的 node_modules**，包级的按需再补：

```bash
ln -s /Users/fengzheng/德国Box系统/node_modules  <worktree>/node_modules
# 起服务时直接用根 .bin 的绝对路径，别依赖相对路径解析
cd <worktree>/customer-portal && exec <worktree>/node_modules/.bin/vite --port 5177 --strictPort
```

## 附带踩到的第二件事：端口被邻居项目的 vite 占走了

全局端口表把 5174/5175/5176 分给了 EU-TMS 三端，但实测：

```
lsof -nP -iTCP:5175        # → PID 86557，cwd = /Users/fengzheng/sysafari-logistics
```

sysafari 的 vite 在 5173 被占时会**自动递增**到 5174、5175，
直接坐到了 EU-TMS 的号段上。而 `customer-portal/vite.config.ts` 是 `strictPort`，
被占就直接报 `Port 5175 is already in use` 起不来。

- 起服务前先 `lsof -nP -iTCP:<端口>`，**看到进程要先看它的 cwd 属于哪个项目**，
  别直接 kill——那可能是别的项目/别的对话正在用的。
- 临时验证用一个没人占的端口（本次用 5177 / 5194）就行，
  不必为了守端口表去动别人的进程。
- ⚠️ `lsof -sTCP:LISTEN -t` 有时抓不到只在 IPv6 上监听的进程，
  查端口占用要用不带过滤的 `lsof -nP -iTCP:<端口>` 复核一次。

## 防护规则

- **worktree 里准备依赖，先看仓库是不是 workspace**（根 `package.json` 有没有
  `workspaces` 字段）。是的话，根 `node_modules` 是必须软链的那一个。
- **判断依赖是否可用，不要只看目录在不在**，直接 `ls node_modules/.bin/<要用的命令>`。
- 软链 `node_modules` 属于本地验证的临时设施，**提交前必须确认没有被 add 进去**：
  `.gitignore` 里的 `node_modules/`（带斜杠）**不匹配软链**，
  `git status` 会把它列成未跟踪的 `??`。全程用 pathspec 提交（只列自己改的文件），
  绝不 `git add -A`（全局 CLAUDE.md 记过一次真实事故）。
