# 033 · 前端字段名凭想象写，整列长期空白却不报任何错

> 发现日期：2026-08-03（P9 做承运商门户三语时，Frank 看页面才发现）
> 涉及文件：`carrier-portal/src/pages/TransportTasks.tsx`、`carrier-portal/src/pages/Billing.tsx`

## 问题现象

承运商门户「运输任务」页：**订单号列全空、路线只剩一个箭头 `→`、类型和重量全是 `-`**。
「费用结算」页：**订单号、描述、到期日、付款日全空，「待结算金额」卡片永远显示 0**，
不管库里有多少笔应付。

这些不是新 bug——从页面写出来那天就是坏的，**中文界面下同样空白**，
只是一直没人逐列核对过，直到做多语言时盯着看才暴露。

## 根本原因

前端 `interface` 的字段名是**按直觉起的**，没跟后端实际返回对照：

| 前端写的 | 后端实际返回 | 结果 |
|---|---|---|
| `orderNo` | `order_number` | `undefined` → 空白 |
| `originCity` / `destinationCity` | `pickup_city` / `delivery_city` | `undefined` → 只剩箭头 |
| `containerType` | 压根没这字段 | 恒 `-` |
| `weight` | `cargo_weight_kg` | 恒 `-` |
| `status` | `payment_status` | 状态徽章显示原始值 |
| `dueDate` / `paidDate` | `due_date` / `paid_date` | 空白 |
| `description` | `remarks` | 空白 |

**TypeScript 一个字都不会报**：后端返回的是 `any`（`ApiResponse<Payable[]>` 只是断言，
运行时不校验），访问不存在的属性得到 `undefined`，React 渲染 `undefined` 就是空字符串。
**没有红字、没有崩溃、控制台干干净净**，页面就这么静静地空着。

## 同一批里更隐蔽的两个

### 1. 枚举值凭想象写 → 汇总恒为 0

```tsx
// ❌ PENDING / APPROVED 是想当然的，数据库 payment_status 根本没这两个值
const totalPending = payables
  .filter(p => p.status === 'PENDING' || p.status === 'APPROVED')
  .reduce(...)
```

`financial_records.payment_status` 的真实取值是
`UNPAID / PARTIAL / PAID / OVERDUE / VOID`。筛选条件永远匹配不上 →
**过滤结果恒为空数组 → 求和恒为 0**。这比空白更危险：**空白看得出来是坏的，
一个"0 €"看起来像是"确实没有待结算"**，业务上会直接误判。

### 2. 单位凭想象写

```tsx
{order.weight ? `${order.weight}t` : '-'}   // 后端字段是 cargo_weight_kg（公斤）
```

字段名接对之后，`12000` 公斤会显示成 **"12000 t"**（一万二千吨）。
字段名错的时候反而看不出来，一修字段名这个错就跟着上线了。

## 正确做法

1. **前端 interface 直接抄后端的 snake_case**（项目规范第 4 条），不做 camelCase 转换：
   ```tsx
   interface Order {
     order_number: string
     pickup_city: string | null
     cargo_weight_kg: number | string | null   // NUMERIC 可能是字符串，踩坑 002
   }
   ```
2. **枚举值一律回数据库/迁移文件核对**，不照抄别的页面、不凭语感：
   ```bash
   grep -n "CREATE TABLE financial_records" -A 30 server/database/migrations/100_*.sql
   ```
3. **带单位的字段，单位从字段名读**（`cargo_weight_kg` → kg，`amount` → 看 `currency` 列）。

## 防护规则

1. **写任何列表页之前，先把接口的 SQL 拉出来看一眼实际返回的列名**——
   ```bash
   grep -n "SELECT" -A 15 server/modules/<模块>/routes.js
   ```
   这一步 30 秒，省掉的是"上线三个月没人发现整列是空的"。
2. **改完页面必须拿真实数据看一遍每一列**，不能只看"页面能打开、不报错"。
   空白列和恒 0 的汇总卡片是这类 bug 的典型长相。
3. **凡是 `filter(x => x.status === '常量')`，那个常量必须能在迁移文件里搜到**。
   搜不到就是写错了。
4. 后端改字段名/枚举时，全仓库搜一遍前端有没有硬编码用到。
